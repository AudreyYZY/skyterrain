# 地形集选取标准与分类定义

> 本文档回答：**为什么是这些地形、为什么这样分类**。
> 在此之前，`CLAUDE.md` 只写了「怎么加一个地形」（注册表条目 + 相机 + 内容 4 步），
> 没有写「收哪些、按什么分类」。这套地形集是增量长出来的（先中国、后澳大利亚，再逐步扩展到
> 其它国家），分类逐个拍定，存在不一致。本文档给出标准，并据此审计、列出改动清单。

状态：**草案，待审。** 审定后：① 更新 `lib/terrain-registry.ts` 分类 ② 更新 `CLAUDE.md`
③ 按清单增删条目。

## 1. 产品目的决定选取原则

Flight Geography Explorer 是**地貌认知系统**：让不了解这些地形的人，从飞机舷窗视角，
快速、全面、正确地建立对一个国家/地区地表结构的认知。

由此，地形集不是「著名景点列表」，而是一份**教学用地貌图集**。收录一个地形的理由只有两类：

1. **它是理解这片土地地表结构的必要拼图**（骨架）——不讲它，就讲不清这个国家的地貌怎么组织。
2. **它是普通旅客会真的飞越、并且一眼能认出名字的标志地物**（锚点）——提供记忆抓手。

不满足这两类的（某条从属小山、某个只有专业者知道的次级单元、某个纯人文的城市），
不进地形集。

## 2. 选取分级（Tier）

| Tier | 定义 | 纳入判据 | 规模控制 |
|---|---|---|---|
| **T1 骨架** | 不讲它就讲不清该地区地表结构的地形 | 三级阶梯的界线、四大高原/四大盆地/三大平原一类的一级单元、主干山脉、主干河流的signature 河段 | 全部必收，一个不少 |
| **T2 地貌省** | 有清晰独立个性的次级地貌区 | 有自己的地貌类型 + 范围 + 走向，且讲的故事**不被某个 T1 条目覆盖** | 用来补「覆盖矩阵」的空格；覆盖已足时不再加 |
| **T3 标志地点** | 名气大或单帧画面极强的**具体一处** | 不是一个区，是一个点/一小片；有强名称识别度 | 每个 region ≤ 8，防止退化成景点清单 |

**每个 region 必须先列全 T1 清单**（见 §4），再用 T2 填覆盖矩阵，最后限量放 T3。

## 3. 分类定义（Category）

### 3.1 现状问题

- `lib/terrain-registry.ts` 有 **15 个 category**；UI（`ExplorerApp.normalizeType`）压成 **11 个侧边栏组**；
  `scenic` / `oasis` / `city` 全压进「景观」。
- 另有一份**过时的** `types/terrain.ts` `TerrainCategory`（`mountain_range` / `silk_road` 等），
  与注册表定义分叉，靠 `normalizeType()` 硬桥接。注册表是单一真实源，这份应废弃。
- `scenic` 是「塞不进别的类」的杂物抽屉：里面混了草原、峡谷、珊瑚礁、岛山 4 种不同地貌。
- `city` / `oasis` 不是地貌。

### 3.2 目标分类集（提案）

每类给一条**纳入判据**。地貌类优先；人文单独分层。

| category | 中文 | 纳入判据 | 备注 |
|---|---|---|---|
| `mountain_system` | 山脉 | 有连续主脊线和明确走向的山脉/山群；**不是单峰** | 见 §5 山脉审计 |
| `plateau` | 高原 | 大面积隆起、内部相对平坦的高地 | 干净，保留 |
| `basin` | 盆地 | 四周高、中间低的封闭低地 | 干净，保留 |
| `plain` | 平原 | 低平的堆积地面（含冲积、三角洲） | ✅ **`delta` 并入 `plain`**（已定） |
| `hills` | 丘陵 | 相对高差 < ~200 m 的低矮起伏地 | 火焰山、雷州半岛需重判（见 §6） |
| `desert` | 沙漠 | 风成沙漠、沙地或砾质戈壁 | 保留 |
| `lake` | 湖泊 | 湖泊 | 保留 |
| `river` | 河流 | 河流的代表性河段/河谷 | 保留 |
| `valley` | 河谷·走廊 | 两山之间的狭长低地（河谷或构造走廊） | 河西走廊、伊犁河谷；见 §6 |

| `settlement` | 绿洲·聚落 | ✅ **`oasis` + `city` 合并为此**（已定）。人文-地貌交界层，见 §8 | 独立子系统，不与纯地貌类混排 |

**决定已锁定**（§9 全部落实）：(a) `delta`→`plain` ✅　(b) 新增三类 ✅　
(c) `oasis`/`city` → 合并为 `settlement` 人文层，见 §8 新方法 ✅　(d) `大堡礁`→`coast` ✅

| 岛 | 结论 |
|---|---|
| 海南岛、台湾岛、塔斯马尼亚岛 | 保留（均有独立山系 + 垂直带） |

| K'gari / 弗雷泽岛（澳洲） | ✅ **新增**。世界最大沙岛——例外收录：它虽是单一沙质地貌，但"整座岛由沙构成、还长着雨林"本身就是罕见地貌现象，教学价值高 |

K'gari 作为"地貌本身即奇观"的例外补入。

## 8. 人文条目的处理方法（`settlement` 层）

现有：`city` = 喀什、和田、吐鲁番；`oasis` = 巴楚、麦盖提。这五个不是地貌。

**用户意图**：不删。想让用户即使没去过、也能了解这些"可能只有本地人知道、没什么旅游价值"
的地方；工具若能覆盖足够多地方会很有用。但也清楚——把全国、全世界的城镇都覆盖会非常难。
因此需要一个**有边界、可持续**的方法，而不是无限铺点。

### 8.1 定位：这是一个独立子系统，不是地貌图集的一部分

- 地貌图集（§2 的 T1/T2/T3）保持纯粹、有限、可完成。
- 人文地标另开一层 `settlement`，**明确标注为"人文-地貌交界"**，在侧边栏单列一组
  「绿洲·聚落」，视觉上（标签样式、颜色）与地貌类区分。
- `city` + `oasis` 合并进 `settlement`，不再有"城市 vs 绿洲"的分裂。

### 8.2 收录判据：必须"挂靠"在骨架上，增长才有边界

一个聚落进 `settlement` 层，必须满足**至少一条**：

| 判据 | 说明 | 例 |
|---|---|---|
| **H1 区域锚点** | 是某个已收录地貌区的**代表性聚落**——讲那片地貌绕不开它 | 喀什（塔里木盆地西缘绿洲链）、张掖（河西走廊）、拉萨（雅鲁藏布河谷） |
| **H2 航线沿途** | 位于某条已有 `data/routes/` 航线的正下方或邻近，飞越时会看到 | 和田、吐鲁番 |
| **H3 地貌样本** | 这个聚落本身**演示了一种人地关系模式**（绿洲农业、通道城市、资源城市） | 巴楚、麦盖提（塔里木缘的小绿洲聚落链，演示"扇形绿洲串珠"） |

**不满足任何一条的聚落不收。** 这条规则让 `settlement` 层的增长被"已收录的地貌区 +
已有航线"这两个有限集合限死——不会失控成"全球城市数据库"。

### 8.3 每个 region 的配额

`settlement` 条目 **每个 region ≤ 8**。某 region 的地貌图集（T1/T2/T3）完成前，
不新增该 region 的 `settlement` 条目。全球扩展时：每个新国家**先做完地貌图集**，
再按 H1/H2 补 2–4 个锚点聚落即可，不追求城镇完整性。

### 8.4 讲解模板：聚落用 3 段，不用地貌的 6 段

地貌讲解的"地貌特征 / 与相似地形区分"对城市不适用。`settlement` 用独立模板：

1. **位置与地貌背景** — 它坐落在什么地貌上、水从哪来
2. **为什么在这里** — 绿洲 / 通道 / 资源 / 军政，人如何利用这片地貌
3. **历史与人文** — 简史、民族、文化标志

（实现：`TerrainLesson` 加可选 `settlementLesson` 分支，或复用 `seeing / observation /
history` 三段并在 `resolveLesson` 里对 `settlement` 类跳过其余段。）
