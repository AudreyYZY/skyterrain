## Executive Summary

**Flight Geography Explorer** is a documentary-style web application for recognizing Earth's landforms from an airplane window perspective. Not a GIS dashboard, not a flight simulator, not a game.

### Three Core Subsystems
1. **3D Rendering** — CesiumJS globe with auto-derived camera, cinematic labels, and flight routes
2. **Narration System** — TTS pipeline from terrain data → structured lesson → SSML → speech with sentence-level highlighting
3. **Terrain Data** — 34 JSON terrain definitions organized through a central hub, with AI-powered photo identification

### Three Key Data Flows
1. **Camera**: `Geometry → FOI Registry → auto-camera.ts → Cesium.Camera.flyTo()`
2. **Narration**: `TerrainPoint → narration-engine / lesson.ts → speakAndWait() → WordBoundary highlighting`
3. **Photo ID**: `PhotoModePanel → compress-image → API route → mimo-photo.ts → OpenAI Vision → fallback`

### Three Architectural Characteristics
1. **Dual Data Model** — TerrainPoint (16 consumers, legacy) coexists with GeographicFeature (3 consumers, next-gen)
2. **FOI Registry** — 1,183-line registry mapping each terrain to camera-worthy Points of Interest
3. **Auto Camera** — No manual camera coordinates; all computed from geometry + FOI position

### Three Technical Risks
1. 🔴 **God Component** — CesiumMap.tsx: 1,707 lines, 292 symbols, ~40 methods across 5 subsystems
2. 🟡 **Dual Models** — Two parallel terrain data representations with migration in progress
3. 🟡 **Large Static Data** — foi-registry.ts (1,183 lines) and i18n.ts (217 lines) contain inline data dictionaries

## Core Pipelines

### Camera Derivation Pipeline

```
GeographicFeature.geometry (Polygon | RidgeCorridor)
  → foi-registry.ts / getTerrainFOI()
    → primary FOI (lon, lat, type) + geometryCoords
  → auto-camera.ts
    ├─ extractPolygonCoords() / extractLineCoords()
    ├─ computeBBox()
    ├─ computeCameraFromRidge()
    │   ├─ computeMountainHeading()
    │   ├─ computeRangeForSpan() → min()
    │   ├─ clamp() → max()/min()
    │   └─ offsetPositionForHeading() → tan/abs/asin/sin/cos/atan2
    └─ CameraParams { target, heading, pitch, range }
  → CesiumMap.cameraAt() → Cesium.Camera.flyTo()
```

**cameraAt callers:**
- `flyToTerrain()` in `components/CesiumMap.tsx`
- `flyToTerrainAndWait()` in `components/CesiumMap.tsx`
- `flyLeg()` in `components/CesiumMap.tsx`

### Narration Pipeline

```
TerrainPoint (34 JSON, each with lesson field)
  ├─ lib/narration-engine.ts
  │   ├─ generateNarrationFromTerrainData() — structured narrative
  │   ├─ generateFlyoverNarration() — flyover cue
  │   └─ generateRouteNarration() — route description
  ├─ lib/lesson.ts
  │   ├─ lessonToSpeech() — TerrainLesson → plain text
  │   ├─ lessonToSSML() — TerrainLesson → SSML markup
  │   └─ terrainToSpeech() — TerrainPoint → full speech text
  ├─ lib/mimo.ts (OpenAI) — generateLesson() → dynamic AI narration
  └─ lib/speech.ts / speakAndWait() → Edge TTS / browser fallback
       └─ useSentenceHighlight → WordBoundary highlighting → StructuredLesson
```

### Photo Identification Pipeline

```
PhotoModePanel → compress-image.ts → api/photo-identify → mimo-photo.ts
  ├─ buildCatalog() → buildTextPrompt() → callTextModel (OpenAI Vision) → parseResult()
  └─ (AI fail) → photo-fallback.ts → resultFromTerrain() / guessPhotoFromHint()
```

### Flight Route Pipeline

```
ExplorerApp → CesiumMap.flyRoute(route, callbacks)
  ├─ routes.ts / resolveRouteWaypoints() → resolveWaypoint() → getTerrainById()
  ├─ preloadRoute() — preload terrain tiles
  └─ for each waypoint → flyLeg(from, to, route)
       ├─ cameraAt(dest) → sampleTerrainMostDetailed
       ├─ legDurationSec() → flyTo() → waitForTilesSettled()
```
