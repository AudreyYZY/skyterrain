### 可执行的核实标准

对每个城市的 6 个字段（identity/layout/gettingAround/culture/seeAndDo/whenAndTips），
逐句区分：

- **通用地理常识**（"建在河边""属地中海气候"）→ 不需要核实，风险低。
- **具体、可证伪的陈述**（数字、精确日期、"第一/唯一/最大/最古老/世界最…"这类最高级、
  排名、具体历史事件、专有名词背后的机制）→ **必须 WebSearch 核实**，权威来源优先
  （官方机构、UNESCO、维基百科交叉印证、政府旅游局等）。
- 核实后发现错误 → 直接改写为准确表述（不是加"据称"敷衍过去）；如果是学界本身有争议的
  说法而原文已经用"之一""被称为""相传"等做了合理限定 → 视为已经达标，不用再改。
- 已经写得扎实、核实无误、也不算"单薄"的国家 → **不需要额外改写**，核实完直接过，
  不用为了"看起来有产出"而强行加内容。
- **时效性陈述也算可证伪陈述**：本轮发现的错误里有相当一部分不是"写错了"，而是"写的时候
  对、后来变了"（美国 2025 年行政命令定英语为官方语言、拉斯维加斯海市蜃楼酒店 2024 年
  关闭火山秀停演、丁格尔海豚 2020 年失踪、沃特福德机场停飞、都柏林—凯里航线 2021 年
  起改为瑞安商业运营不再补贴、希姆肯特 2018 年升直辖市、基督城大教堂 2024 年停工……）。
  以后新增内容时，凡是"目前/仍在/正在"这类现在时陈述都要查一下最新状态。

## 4. 标准工作流（以后新增国家/城市时对新增部分重复这一套）

1. `grep -B2 'country: "国家slug"' lib/places-registry.ts | grep 'id: "' | sed -E 's/.*id: "([a-z-]+)".*/\1/'`
   拿到该国全部城市 id。
2. 对每个 id 跑 `grep -n "^  $id: {\|^  \"$id\": {" lib/travel-content.zh.ts`，定位起始行号
   （注意：id 里带连字符的 key 会被写成 `"kitzbuhel-city": {` 这种带引号形式，两种 grep 模式都要试）。
3. 用 Read / sed 把该国所有城市的 6 段内容整段读出来。
4. 逐城市扫一遍，列出所有"具体、可证伪"的陈述（数字/日期/最高级/排名/历史事件/专有机制/
   "目前仍在"类时效陈述），按风险从高到低排序。
5. 批量并行发起 WebSearch 逐条核实（每次对话轮次可以并行发起 5-10 个查询）。
6. 核实结果：
   - 全部无误 → 不改动，记录"核实完成，无需改动"。
   - 发现具体错误 → 同时修改 `lib/travel-content.zh.ts` 和 `lib/travel-content.en.ts`
     对应字段。**中文字符串里出现的引号一律用中文弯引号 “ ”，绝对不能用直引号 "，
     否则会破坏 TypeScript 字符串边界导致 `tsc` 报语法错误**（这个坑在本任务里踩过至少 3 次：
     太原、合肥、博洛尼亚，每次都是同一个原因）。本 session 用的办法：写一个小 python 脚本
     做精确字符串替换，替换前 `assert s.count(old)==1`，比手工 Edit 稳。
   - 该国若整体偏"概览体"（缺乏因果叙事、只是罗列信息）→ 用新核实的事实给最多一两个城市的
     identity/layout 字段加一点因果解释（参考越南/泰国/马来西亚/韩国/蒙古的加深度方式），不要
     对每个字段都硬套文学化语言（gettingAround/whenAndTips 等实用信息字段不需要加深度）。
7. 改完后依次跑：
   ```bash
   npx tsc --noEmit
   node --experimental-strip-types scripts/check-places.ts   # 期望仍是 "467 城市, 38 概览, 1997 POI, 0 项异常"
   npm run build
   rm -rf .next
   ```
8. `git add lib/travel-content.zh.ts lib/travel-content.en.ts`，写一条中文详细提交信息
   （说明核实了哪些具体陈述、发现了什么错误、如何修正），结尾加当前会话规定的
   `Co-Authored-By` 行，然后 `git push`。
9. 回来更新本文档的"已完成"表格，再 commit 一次本文档（文档单独一个 commit，不和业务代码
   混在一起，这是仓库既有的提交规范）。

小时/天重置）。第一个 session 在瑞士中途用完；第二个 session 用约 120 次做完剩余 12 个国家。
