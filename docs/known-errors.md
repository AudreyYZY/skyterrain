# 已犯过的错误：类型、实例、根因、防线

> 这个项目的文字与数据是依据公开资料整理生成的，**没有人逐条审核过**。
> 已经发现并修掉的事实错误不在少数，还没被发现的一定也有。
>
> 这份文件不是"注意事项清单"，是**错误台账**：每一类都写清楚犯过什么、为什么会犯、
> 怎么修的、现在有没有自动防线接住、以及**还会不会再犯**。
>
> **用法**：
> - 新发现一个错误 → 先找它属于下面哪一类，把实例补进那一类的"实例"表。
> - **归不进任何一类 = 这是新类型**，那就新开一节，并且**必须同时想清楚防线**
>   （新增一条自检、或者明确写下"只能靠联网核实"）。
> - 每一类的"防线"一栏只有三种值：**脚本**（有自检拦得住）、**流程**（要靠
>   `/verify-content` 联网核实）、**无**（目前只能靠人撞见）。
> - GitHub issue 用 `data-error` 标签，正文第一行写它属于本文件的哪一类。

### A1-b 方向反了：记的是回程航班号

出现了 **7 次**，多到该单独说：`xiy-yzy`（MU6202 是张掖→西安的回程）·
`mel-adl`（QF680 是阿德莱德→墨尔本）· `scl-puq`（LA82 是蓬塔阿雷纳斯→圣地亚哥）·
`kul-bki`（AK5109 是亚庇→吉隆坡）· `ala-cit`（KC972 是希姆肯特→阿拉木图）·
`nqz-plx`（KC7352 是谢梅伊→阿斯塔纳）· `nqz-pwq`（IQ372 是巴甫洛达尔→阿斯塔纳）。

**特征**：航司通常给去程与回程分配相邻号（去程奇数、回程偶数，或 N 与 N+1）。
写入时查到一个号、看到城市对里有这两座城市就用了，没注意方向。

**核实要点**：搜索结果里的「X → Y」要逐字看方向，不能只看两个城市名对不对。

---

**根因**：写入时把"这条城市对有直飞"和"这个航班号飞这条线"当成了同一件事。
航班号是从检索结果里顺手取的，没有回到航司时刻表逐条对。中国国内线抽查 24 条错了 19 条，
**错误率约 79%**；国际线抽查 35 条错了 9 条（多为机型漂移而非航线错），约 26%。

**修法**：`types/route.ts` 加 `FlightRoute.source = { ref, checkedOn, status?, note? }`；
`lib/routes.ts` 的 `isFlightVerified()` 是**唯一出口**，界面、搜索、解说都走它；
查过但查明有误的记 `status: "wrong"`（与未核实同样不显示，但记住已经查过，避免重复劳动）。
`npm run check:routes` 硬性拦截"未核实航线的解说里点名了机型或航班号"。

### A2 机型漂移

| | |
|---|---|
| **症状** | 航班真实存在，但机型写错或已换代 |
| **防线** | **脚本**（解说里的机型必须与 `flight.aircraft` 对得上）+ **流程** |
| **还会再犯吗** | **会**，而且是必然：航司换机不通知任何人。`checkedOn` 就是用来判断快照多旧的 |

实例：上海—奥克兰 MU779 原记 787-9、实际 777-300ER；广州—悉尼 CZ325 原记 787-9、
实际 A330-300；北京—华沙 CA737 原记 777-300ER、实际 A330-300；北京—海口 HU7282
原记 787-9、实际 737-800；北京—首尔 CA123 原记 A330-300、实际 A321；北京—东京 CA181
原记 787-9、实际 A321；北京—上海 MU5104 原记 777-300ER、实际 A330-200/300；
北京—福州 CA1505 原记 737-800、实际 A321neo。

**整支机队退役是最狠的一种**（2026-09-07 挪威批新发现）：**SAS 已于 2023-11-19 退役
最后一架波音 737**，现主力是 A320neo/A321neo + SAS Link 的 E195。可记录里 5 条挂 SK 号的
挪威国内线**全写着 Boeing 737-700/800** —— 整批停在退役前的旧口径。同理德国那批：
**Lufthansa CityLine 已于 2026-04-18 永久停运**，它原来代管的支线记的 Embraer 190 也整批过时。

哈萨克斯坦批又抓到两起，都出自同一家：**Air Astana 的 757 机队 2020 年就全部退役**
（记录里还写着 Boeing 757），**E190-E2 机队 2025-05 全部退役**（记录里还写着 Embraer E190）。
一家航司在两个机型上各留了一处过期记录。

这类的特征是**一查一批**，不是一条一条错。发现一例就该全库排查同承运人同机型的其他条目
（德国那次排查过了没有扩散；挪威 5 条全中；哈萨克斯坦 2 条）。

**根因**：机型是航线里最易变的字段，却被当成静态属性写死。

### A3 经停航班冒充直飞

| | |
|---|---|
| **症状** | 同一个航班号中途经停，被当作不经停直飞收录 |
| **防线** | **流程** |
| **还会再犯吗** | **会**。检索结果常常不区分"直飞"与"同机号经停" |

实例：广州—拉萨 CZ3463 实为广州**经停重庆**再飞拉萨（全程 5h45m），机型也不是 A330-200
而是 A319。已按项目既有口径（不用经停航班冒充直飞）标为 `wrong`，暂不显示航班信息。

同类的**正确处理**已有先例：卢森堡（纯货运）、冰岛（经停哥本哈根的第五航权）、
克罗地亚（经停布加勒斯特的同机号）三国查无真正不经停直飞，如实标注缺口未收录，
没有编造经停航班充数。捷克国内查实**无商业航空网络**，本国一条国内航线都不收。

### A4 航线本身已停飞，航班号被复用

| | |
|---|---|
| **症状** | 写入时确实有这条不经停航线，之后航司停飞，那个航班号被挪去飞别的城市对 |
| **防线** | **流程** |
| **还会再犯吗** | **一定会**。这是纯时间衰减，而且比 A2 机型漂移更隐蔽 —— 航班号还"活着"，只是不飞这条线了 |

2026-09-07 核实中国国内航线时新发现的一类，与 A1 不同：A1 是**写入时就错**，A4 是
**写入时对、之后自己变错**。

实例：

- **成都—格尔木 TV9965** —— 2024-07-30 中新网报道格尔木⇌成都双流直飞开通，去程
  正是 TV9965、西藏航空 A319、每周二/四/六，此前需经停西宁。写入时完全属实。
  但现在成都至格尔木**已无直飞**（只剩经西宁/拉萨/郑州中转），而 **TV9965 这个号
  已被复用为重庆江北→大理**。两条独立证据互相印证。
- **上海—景德镇** —— 深航 2024 冬春航季确有 ZH9540 虹桥→景德镇（A320，每日），
  现在景德镇的直飞城市只剩北京首都/大兴、成都天府、宁波、天津、西安、广州，
  上海只在"需经停"一栏；ZH9540 这个号已改派沈阳→广州。

**为什么危险**：如果只核"这个航班号存不存在"，A4 会全部漏过 —— 号还在，飞的却是
别处。核实时必须同时确认**航班号服务的城市对**，而不只是航班号本身。

**处理（2026-09-07 起改为整条移除）**：一开始的做法是标 `status: "wrong"` 不填替代值，
航线照常可飞、只是不显示航班号。但这样等于把一条**现实中飞不了的航线**留在库里，
「界面不显示航班号」读起来像技术限制，而不是「这条线不存在」。

项目既有口径本来就是**不用经停航班冒充直飞**（捷克国内查实无商业航空网络，就一条国内
航线都不收）。所以这一类现在**整条移除**：航线 JSON + manifest 注册 + 中英文两套解说 +
逐句锚点表一起删。

### A5 承运人已停运或被接管，名称过期

| | |
|---|---|
| **症状** | 航班号还在飞、航段也对，但记的承运人已经不存在了 |
| **防线** | **流程** |
| **还会再犯吗** | **会**。航司并购重组是常态，而两字代码往往被继承下来，所以从航班号上完全看不出来 |

原型：**意大利那 7 条**全写着「意大利航空 Alitalia」，而 Alitalia 已于 **2021-10 停运**，
由 **ITA Airways 接手并沿用 AZ 代码**。航班号照飞，承运人是死的。

同批还有一条更彻底的：罗马—卡利亚里（`fco-cag`）不只是名称过期 —— 撒丁大区 2026 年
新一轮「领土连续性」招标把这条线整体判给了 **AeroItalia**，ITA 现在根本不飞这条不经停线。

**同类还抓到三起**：
- **MASwings → AirBorneo**（2025 年被砂拉越州政府收购，2026-01-02 起启用新品牌，IATA 仍是 MY）
- **Qazaq Air → Vietjet Qazaqstan**（2024-12-24 被 Sovico 集团财团收购，2025 年起改名，IATA 仍是 IQ）
- **联合航空退出 JFK**（2022-10，时刻额度不足）—— 这是**新变种**：不是承运人停运，
  是承运人**退出了这个机场**，公司还好好的，只是不服务这对城市了。

**反面例子也记一条**：`ala-hsa` 的承运人 FlyArystan 自 2025-01-01 起启用独立 IATA 代码 FS
（此前与母公司 Air Astana 共用 KC），**记录跟上了这个变化**。品牌变更不必然导致错误，
只是没人盯就会漏。

**为什么危险**：只核「这个航班号飞不飞这条线」会完全漏过 —— 号是对的，飞的也对，
错的是它前面那三个字。核实时必须**分开确认航班号与承运人**。

### A6 航班号是写入时随手编的占位号

| | |
|---|---|
| **症状** | 航班号形状规整（1234、321、345…），查下来根本没有这班，或者是别的航线的号 |
| **防线** | **脚本**（`check:routes` 列出形状可疑的未核实航班号，**只提示不断言**）+ **流程** |
| **还会再犯吗** | **会**，但现在有提示了 |

实例：米兰—威尼斯 `AZ1234`、那不勒斯—卡塔尼亚 `FR1234` —— 两个「1234」。查下来
FR1234 查无此班；AZ1234 倒是真实存在，飞的却是**的里雅斯特→奥尔比亚**，与米兰、
威尼斯都无关。法国那批的 `AF6592`、`AF7602` 同样查不到对应航段。

**为什么脚本只能提示、不能断言**：真实航班号也会长成这样 —— `CA123`（北京—首尔）、
`CZ345`（北京大兴—阿姆斯特丹）、`LH100`（法兰克福—慕尼黑，机场官网可查）、
`5J321`（马尼拉—黎牙实比）、`VJ321`（胡志明市—富国岛）都已核实属实 —— 五个反例。

**但它也命中过一次**：克罗地亚的 `OU345`（实际是萨拉热窝→萨格勒布）与 `OU210`
（查无此号）两个都确实是错的。所以这个信号是**弱阳性**：五次落空、一次命中，
拿来排优先级可以，拿来判错不行。
所以 `check:routes` 只把未核实的可疑号列出来排优先级，不判错。

**最极端的一次是整批编造**：蒙古五条国内线记的是「航蒙航空 M0801 / M0803 / M0805 /
M0807 / M0809 + Airbus A319」—— 五条不同航线用一串连号奇数。查下来 **Aero Mongolia
当前根本没有任何蒙古国内定期航班**（只飞首尔/东京/呼和浩特三条国际线），五个号一个都
不存在。实际承运人是 MIAT（CRJ-700，2024-04 才恢复国内线，此前空窗 15 年）。
这一批不是「抄错」，是凭空生成的。

**不只是航班号，臆造的精确数字也算这一类**：华沙—波兹南记的飞行时长是 **39 分钟** ——
本批唯一一个精确到个位数的时长，其余全是 50/55 这样的整数。查下来时刻表是
10:25–11:20、block time **55 分钟**，多个独立来源一致，**39 分钟没有任何来源支持**。
精确得反常的数字，往往正是编出来的那个。

### A7 代码共享号被当成自营航班

| | |
|---|---|
| **症状** | 航班号能买到票、航段也对，但实际执飞的是另一家航司，机型自然也跟着错 |
| **防线** | **流程** |
| **还会再犯吗** | **会**。购票页面显示的就是出票方，不点开看不到「由某某航空执飞」 |

实例：马赛—阿雅克肖、尼斯—阿雅克肖两条科西嘉航线记的是**法国航空 A319**，实际
唯一执飞不经停航班的是**科西嘉航空（Air Corsica），机型 ATR 72** —— 法航在这两条线上
没有自营运力，只用 AF 前缀代码共享出票。机型从 A319 到 ATR 72 是两个量级的东西。

同类嫌疑还有里昂—马赛（实际是法航支线 HOP! 执飞）、以及中国国内线里 `9` 开头的
四位号（CA9747 核实下来是国航自己飞，不是代管 —— 说明这个嫌疑也可能不成立，
必须逐条查而不是按号段推定）。

**湿租（wet lease）是同一类里最容易漏的**：瑞典六条国内线里有四条（马尔默、维斯比、
卡尔马、奥勒）挂的是 SAS 的 SK 号、品牌也是 SAS，**实际由 Braathens Regional（BRA）
用 ATR 72-600 湿租代运营**。这不是代码共享——票是 SAS 的票、号是 SAS 的号，只有飞机
和机组是别人的。记录里六条全写着「A320neo」，而涡桨 ATR 72 与喷气 A320neo 连飞行时长
都差一大截（马尔默线实际 90 分钟，记录写 55 分钟就是按喷气机算的）。

**丹麦三条也是同一家 BRA**（哥本哈根—奥胡斯/奥尔堡/比隆）：SAS 自 2024-09 与
Braathens Regional 签了 7 年 ACMI 协议，2025-01 起从原代运营方 **Xfly（2024 年底破产
清算）** 转由 BRA 执飞。**我猜代运营方是 DAT 或 Xfly，实际是 BRA** —— 湿租这个方向
猜对了，具体是谁猜错了，又一次印证「结构性怀疑靠谱、细节猜测不靠谱」。

**哥本哈根—博恩霍尔姆则更进一步**：那条根本不是 SAS 在飞，是丹麦政府招标的 PSO 航线，
中标方与运营方是 **DAT（品牌 Bornholmerflyet）**，真实号是 DX 系列、机型 ATR 72，
而记录写的是「北欧航空 SK6207 / A320neo」—— 承运人、航班号、机型三项全错。

**核实要点**：查到航班号之后还要再问一句「**谁在飞**」。

## B 类 · 地名与设施变更

### B1 机场更名/迁建未跟进

| | |
|---|---|
| **症状** | 写入时正确，之后官方更名或迁建，文本停在旧名 |
| **防线** | **半条**：`check:places` 能挡住「改了一处忘了另一处」，挡不住「改名了而我们不知道」 |
| **还会再犯吗** | **一定会**。这是纯时间衰减，写得再对也会过期 |

实例：

- **乌鲁木齐地窝堡国际机场 → 乌鲁木齐天山国际机场**（2025-03 民航局批复，IATA `URC`
  与坐标不变）。已在 `places-registry` + 4 条 urc 航线航点 + `travel-content` 双语修正。
  写这份台账时发现 `data/routes/pek-urc.json` 的 `source.note` 里还留着旧名，已一并改成
  "天山（原地窝堡，2025-03 更名）" —— 留痕本身也会过期。
- ⚠️ **2026-09-11 更正：下面这一条本身写早了。** 盛乐机场 2026 年只完成了验收与演练，民航局计划 **2026-11-27** 才转场，此前航班仍在白塔 —— 把一件尚未发生的迁建写成已完成（与卢森堡米内特「提前完成时」同形），而这一条还被 CLAUDE.md 当成了更名范例。注册表与呼和浩特条目已改回白塔，转场后再改回来。
- **呼和浩特白塔国际机场 → 盛乐国际机场**（迁建至和林格尔县，IATA `HET` 不变，
  坐标改为 40.480, 111.573）。

**根因**：机场名被当成静态字符串写进多个文件（注册表 + 航线航点 + 双语正文），
更名时要同时改四处，漏一处就前后不一致。

**2026-09-08 补上了半条防线**：`check:places` 现在检查**同一个 IATA 在不同城市条目里
名称与坐标是否一致**。52 组机场被多个城市共用（无锡与苏州共用苏南硕放、卢森堡 9 个堂区
条目共用 LUX、萨尔茨堡机场被 4 座城市引用……），每一处都是手写的 —— 而**更名恰恰要同时改这几处**。
建这条检查当天就扫出 7 处不一致：

| IATA | 不一致在哪 |
|---|---|
| `MRS` / `AMS` / `VIE` / `KUL` | 同一座机场，一处写 "…Airport"、另一处没有 |
| `SZG` | 一处「萨尔茨堡莫扎特机场 / Salzburg Airport W. A. Mozart」，另一处「萨尔茨堡机场 / Salzburg Airport」 |
| `LXA` | 拉萨与山南两条写的贡嘎机场坐标差在小数点后第四位 |
| `KWJ` | 全州与光州两条写的光州机场坐标同样差在第四位 |

坐标差 20 米不影响使用，但它说明**同一座机场在注册表里有两份互不相同的记录** ——
更名时改中一份、漏掉另一份，就是这么发生的。

比较前要去掉「（经 X 转乘）/ (via X)」后缀，那是**有意的约定**（表示这座城市自己没有机场），
不去掉的话整批 52 组都会被报出来。

**还是做不到的那一半**：没有脚本能发现"这个机场在外面已经改名了"。
这类只能靠 `/verify-content` 定期把 590 个机场名拿去和官方公告比对。

### B1-b 会改名的不只是机场 —— 地形也会（2026-09-09）

英国地形第 1 批扫出两处：

| 条目 | 现在的官方名 | 从什么时候起 |
|---|---|---|
| `snowdonia` | **Eryri**（主峰 **Yr Wyddfa**） | 2023-11-16 起国家公园管理局以威尔士语名为对外主用名 |
| `brecon-beacons` | **Bannau Brycheiniog** | 2023-04 起 |

原文把这两个威尔士语名写在括号里当作「威尔士语」，等于**把官方名降级成了别名**。
`check:places` 的 IATA 一致性检查只管机场，**地形注册表的 `nameEn` 没有任何一致性检查**，
而且这类改名和机场改名一样，没有脚本能提前知道。

**这次的处理是刻意不对称的，写在这里免得下一轮有人"改回一致"**：

- **英文正文全篇改用官方名**（Eryri / Yr Wyddfa / Bannau Brycheiniog），首次出现处并列旧英语名；
- **中文保留已通行的译名**「斯诺登尼亚」「布雷肯比肯斯」，只在首句注明官方改名。

理由两条：① Eryri / Bannau Brycheiniog 没有既成的中文译名，**生造一个音译等于自造专名** ——
这正是这份台账反复在防的那类事；② 中文正文里直接嵌拉丁串会被 TTS 逐字母念出来。
注册表的 `nameEn` 改成官方名在前（`Eryri / Snowdonia`），旧名保留在斜杠后面 ——
航线锚点的匹配规则本来就会拆开并列名，改完重跑 `gen:anchors` 输出一字未变。

**一次改名要动的地方比想象的多**：`terrain-content.{zh,en}.ts`（两个条目共 20 处，
外加**第三个条目** `lake-district` 的 distinguish 段顺带提到）、`terrain-registry.ts`
的 `nameEn` 与 `source`、`route-narration.ts` 里 lhr-bfs 的英文解说、
`data/routes/lhr-bfs.json` 的 `descriptionEn`。**漏掉任何一处，站内就会同时出现两个名字。**

**第三种：同一轮立法改了两个名字，正文只跟进了其中一个（2026-09-09，新西兰）。**
`mount-taranaki` 的 `history` 段上一句刚写完「2025 年立法把山的官方名定为 **Taranaki Maunga**」，
下一句还写着「**埃格蒙特国家公园**是新西兰第二古老的国家公园」——
而**同一轮立法在 2025-04-01 也把公园改名为 Te Papa-Kura-o-Taranaki 了**。
这次不是隔了一批漏掉（AONB 那次），是**同一段文字里的两个名字，改了一个、漏了一个**。
教训：**改名类的核实，范围不是「这个词」，是「这一次改名动了哪些名字」。**

**第二批又抓到一个，而且是更麻烦的一种 —— 改的是「分类名」不是地名**：
**英格兰与威尔士的全部 AONB（杰出自然风景区）自 2023 年 11 月起统一改称 National Landscape
（国家风景区）**。高尔半岛这一条只是被抽到的那个样本，**这类改名会一次影响一整批条目**，
而单个条目的核实批次根本看不出规模。已在高尔条目里写明「这一档 2023 年 11 月起改称国家风景区」，
并记下：**下一轮要把全库的「杰出自然风景区 / AONB」搜一遍**。

反例同批就有：**南唐斯 2010 年已从 AONB 升格为国家公园**，它的正文写「国家公园」是对的，
**不该跟着一起改** —— 分类名改名的连锁修改里，最容易犯的错是把已经不属于那一类的条目也顺手改了。

**紧接着的一批就证明了这条警告是必要的，而且是被我自己漏掉的**：上面这段写下
「下一轮要把全库的『杰出自然风景区 / AONB』搜一遍」之后，我在**同一个回合**里派出了下一批 ——
**却没有做那次搜索**。下一批的核实方在 `chilterns` 条目里抓到了同一处：正文写的是
「2024 年起**升级**为国家景观」，两个地方都错 —— 时点应是 **2023-11-22**，而且这不是升级，
**法定名称仍是 AONB，改的只是对外使用名**。

**教训不是「分类名改名会漏」，而是「在台账里写下一条待办，不等于它会被执行」。**
现在已经把全库搜完（`lib` 与 `data` 里只有 `chilterns` 与 `gower-peninsula` 两处正文提到这一档，
外加注册表里高尔的 `source` 一行，都已补上现行名）。
**写待办的同一次提交里就把它做掉**，比写一条给未来的自己的提醒可靠得多。

## C 类 · 讲解文字的事实错误

### C1 未加限定的最高级 / 比较级

| | |
|---|---|
| **症状** | "最险峻的一段""第二大的城市"这类无法核实或干脆错误的排名判断 |
| **防线** | **脚本**（`npm run check:claims` 扫未加限定的最高级）+ **流程** |
| **还会再犯吗** | **会**。最高级读起来有力，写作时最容易顺手带上 |

实例：

- **"茶马古道最险峻的一段"**（成都—拉萨解说）—— 无法核实的比较级，违反项目自己写下的
  "去比较性/主观评价"口径。核实到成都—雅安—打箭炉确是真实路段后，删掉"最险峻"。
- **横滨"是日本人口第二多的市"** —— 事实错误。横滨实际是日本人口最多的"市"建制城市
  （约 378 万），大阪第二。原文大概是把"仅次于东京 23 区"和"城市排名第二"混了；
  东京 23 区不是单一"市"建制，不能直接并列排名。
- **达沃"陆地面积菲律宾最大"** —— 这条**是对的**，因为原文已经加了"按行政区划面积计"
  的限定。同一批里它没出问题，正说明**限定语是有效防线**。

**2026-09-08 把 C1a 也收窄了一次：同一条目内部的时间比较不算这一类。**

「4–5月、10–11月气候最舒适」比较的是同一座城市的**月份之间**，不是这座城市与别的地方之间 ——
既可核实又无争议，和「茶马古道最险峻的一段」根本不是一回事。
这类占了 C1a 的三分之一（`最舒适` 114 处 + `最适合` 46 处，几乎全在 `whenAndTips` 段）。

**发现它的是一个不对称**：英文那边一处都没报，因为英文判据里本来就没有 "most comfortable"。
**同一句话中文报、英文不报** —— 两种语言说的是同一件事却只有一边被标出来，
说明是中文这条判据画得太宽了。**中英计数对不上，本身就是判据有问题的信号。**

实现上是**逐个匹配**判断而不是整句放过：一句话里如果既有时间比较、又有一个跨地点的最高级
（「5月最适合来看最壮观的瀑布」），后者照样报。已用五个用例验证过。

**这次 452 → 293 同样是规则收窄，不是内容变好。**

**C1-b 排名被后来的人口变化反超（写的时候是对的）** —— 这一类不是写错，是**过期**，
而且过期的方式比数字更隐蔽：数字过期看得见（年份摆在那里），排名过期看不见
（"最多的市"不带年份，读上去像个恒定属性）。已知实例：

| 条目 | 原文 | 现在 |
|---|---|---|
| 保定 | "河北人口最多的市"（2020 普查含定州 1154 万 > 石家庄 1123 万，当时成立） | 2025 年末石家庄 1124.69 万 > 保定含定州 1008.61 万，**保定已是第二** |
| 儋州 | "海南人口第二多的市" | 三亚 2025 年末 113.60 万居第二，儋州 102.87 万是**第三** |
| 塞维利亚 | "西班牙第四大城市" | 已被萨拉戈萨反超，降到第五 |
| 高松 | "四国最大的城市" | 松山才是四国最大 |
| 芒特甘比尔 | 南澳第二大 | 被维克托港—古尔瓦反超（差 25 人） |
| 釜山 | 「韩国第二大城市」 | 仍成立，但同期仁川 306.1 万 vs 釜山 323.2 万，**差距在缩小**，注释里已记下比较对象 |

**还有一种排名问题不是"被反超"，而是"没说按哪个口径排"** —— 同一座城市在不同口径下名次不同：

| 条目 | 原文 | 实际 |
|---|---|---|
| 里昂 | 「法国第二或第三大城市（与马赛并列）」 | 不是数据不确定：按**城市吸引区**是第二，按**市镇人口**次于马赛排第三 |
| 蒙彼利埃 | 「法国第七大城市」 | 只在按**市镇人口**计时成立 |
| 纳什维尔 | 「全美第 20 大城市」 | 成立，**但要用对口径**：戴维森整县 2025 年约 74.6 万，普查局做城市排名用的是「市县合一政府 balance」（排除县内另设建制的小城市）约 72.1 万 |
| 盐湖城 | 「全美第 46 大都会区」 | **已删**：二手来源分别给 1,308,377 / 第 46 与 1,261,337 / 第 47，没拿到普查局当期排名表就不写名次 |

法国尤其明显，因为 INSEE 有三套并存的地理口径（市镇 / 建成区 / 城市吸引区），
换一套名次就变。美国同理（city / MSA / CSA）。**写「第 N 大」必须带口径**，
写成「第二或第三」会被读成数据本身不可靠。

**但不是所有排名都需要补口径 —— 2026-09-08 把这条规则收窄了一次。**

`C1b` 原来把「第二高峰」「第三长的峡湾」「面积第二大的河漫滩森林」也一起报出来。
这些**被比较的那个量就写在词里**（高度、长度、面积），换个口径名次也不会变 ——
报出来只会逼人写出「日本按海拔计第二高峰」这种废话，而废话会让真正需要口径的那些
（「第二大城市」）淹没在噪声里。

收窄后的判据：

| 报 | 不报 | 为什么 |
|---|---|---|
| 第 N 大 / 第 N 多 / largest / biggest | 第 N 高 / 第 N 长 / 第 N 深 / highest / longest / deepest | 后者的量写在词里 |
| 人口第 N 多 | 面积第 N 大 / 长度第 N | **人口还分市建制/都会区/登记 vs 常住好几档**，横滨那条错的正是这一层；面积没有这个问题 |
| most populous / busiest | —— | 同上 |

**这次下降 288 → 221 是规则收窄，不是内容变好**，台账在这里写明，
免得下一个人把它当成 67 处被修好了。

**还有一种更隐蔽的：口径本身在这个国家不存在。**

| 条目 | 原文 | 实际 |
|---|---|---|
| 林茨 | 「都会区约 82 万」 | 奥地利没有与美国 MSA 对等的官方都会区口径；林茨市政府自己的 Ballungsraum（含 13 个直接相邻市镇）约「接近 30 万」，82.3 万来自英文维基引用的一个更宽泛的统计区，相差近三倍 |
| 维也纳 | 「都会区约 290 万」 | 数字对，但那是**欧盟统计局功能城市区（FUA）** 口径，不是奥地利国内统计 —— 正文必须注明 |
| 塞萨洛尼基 | 「都会区约 110 万」 | 希腊官方口径里没有「都会区」这一档，110 万对应的是**地区单位**（περιφερειακή ενότητα） |

这与 C6-c（口径根本不存在）是同一条线：**写「都会区」之前先确认这个国家的官方统计里
有没有这一档**，没有就用该国自己的说法，并写明是谁的口径。

**处理办法**：更新人口数字时，**同一段里由这个数字派生的排名要一起重算**，
不要只改数字。反过来说，凡是写"第 N 大"的地方，`sources` 注释里要记下比较对象是谁、
是哪一期的数 —— 否则下一轮没法判断它是不是又被反超了。

### C2 两件事被混成一件

| **防线** | **流程** |

（1521-03-31）；宿务是几天后麦哲伦船队为当地王公受洗、并赠予圣婴像的地方。原文把
"第一台弥撒"和"第一次受洗 + 现存最古老圣像"两件事混成了一件。已改写为分别说明两地。

### C6 数字缺年份与口径 ⚠️ 最普遍的一类

| | |
|---|---|
| **症状** | 人口/面积/数量写了一个数，没说是哪一年、按什么口径统计的 |
| **防线** | **脚本**（`npm run check:claims` 逐条列出）+ **流程** |
| **还会再犯吗** | **会**，而且量很大 |

实例：上海 `identity` 段写"都会区人口约 2500 万" —— 没有年份，也没说"都会区"是
市域常住人口、还是都市圈口径，这两个数差很远。同一条目的 `howItWorks` 段反而是**对的**
写法：注释里写着 `// howItWorks sources: Wikipedia: Shanghai; Administrative divisions of
Shanghai (2023 figures…)`，正文里"2023 年常住人口约 581 万"带了年份。

**结论**：`howItWorks` 那一批（691 城，2026-09-06）建立的"每城带 `// sources:` 注释"
是有效做法；早期写的 `identity` / `layout` 段没有这个习惯，是数字失准的重灾区。

**修法方向**（2026-09-07 起动工）：`npm run check:claims` 已经能把"数字附近没有年份"的
句子逐条列出来。524 处**全部在旅游模式的城市/国家概览**里，集中在两段：`identity` 451 处、
`howItWorks` 73 处，涉及 367 个条目（38 个国家概览 + 329 座城市）。按国家分批清。

**写法（本项目的统一格式）**：正文写「**年份 + 口径 + 数字（发布机构简称）**」，
完整来源写进条目上方的 `// identity sources:` 注释。

- 中文：`2024年末常住人口约2480万（上海市统计局）`
- 英文：`a population of about 24.8 million at the end of 2024 (Shanghai Municipal Bureau of Statistics)`
- 注释：`// identity sources: 上海市统计局《2024年国民经济和社会发展统计公报》（2025-03 发布）：2024 年末全市常住人口 2480.26 万人`

三样缺一不可，而且**机构名要能顺畅朗读** —— 这些正文都会被 TTS 念出来，把
《XX年国民经济和社会发展统计公报》整个念一遍是不可接受的，所以完整公报名只进注释。

口径尤其要写清：「都会区」既不是中国的统计口径，也不是澳大利亚的（ABS 用 Greater
Capital City Statistical Area），照抄过来等于自造了一个谁也核不了的量。

**C6-b 国际机构的推算被当成了本国官方数字**（2026-09-07 清国家概览时发现的新模式）：
泰国原文写「人口约7100万」—— 这个数与联合国 World Population Prospects 的推算
（约 7160 万）吻合，而泰国本国官方口径（内政部户籍登记，国家统计局年鉴采用）
是 **6595 万**，两者差约 560 万。UN / World Bank 这类国际机构的数是**模型推算**，
本国统计机构的数是**登记或普查**，方法完全不同，不能混用，也不能拿一个去"验证"另一个。
**正文只写本国官方口径并写明是什么口径**；国际推算与官方数差得远时，把差异写进注释。

同一批还遇到两种相关情形，处理方式记在这里：

- **一国内部有两个并存的官方口径**：韩国的住民登录人口（行政安全部，5112 万）
  与统计厅 KOSIS 的总人口推算（含外国人居民，5168 万）相差 57 万；智利的 2024 年
  普查原始计数（1848 万）与 INE 调节漏报后的 population base（1987 万）相差 7%。
  **取该国统计机构最终采用的那个，并在正文里写明口径**，另一个写进注释。
- **只拿到 2 级来源**（媒体转述官方数字）：波兰人口（PAP 转述 GUS）、蒙古人口
  （新华社转述 NSO）、印尼人口（BPS 官方账号发布而非出版物页面）。可以用，
  但**注释里要写明级别 2**，不要伪装成直接引自官网。
- **拿不到够级别的来源就报 unknown、正文不动**：蒙古「面积约156万平方公里」只找到
  世界银行/FAO 汇编（3 级），没有蒙古官方地籍/统计口径 —— 如实开 issue，
  不给它配一个假的官方出处。

**C6-c 自造了一个不存在的统计口径**（2026-09-07 清中国城市时发现）：30 座中国城市的
`identity` 段写的是「都会区人口」「市区人口」「中心城区人口」—— **这三个说法在中国官方
统计体系里都不是标准称谓**，年度公报只公布「全市常住人口」（含所辖区县）和「城镇人口」
两档。于是这些数字既没有年份，也没有任何官方来源能对得上，等于自造了一个谁也核不了的量。

后果不是「差一点」，是差一倍：

| 城市 | 原文 | 2024 年末全市常住人口 |
|---|---|---|
| 郑州 | 市区约 700 万 | **1308.6 万** |
| 武汉 | 市区约 900 万 | **1380.9 万** |
| 哈尔滨 | 都会区约 550 万 | **985.8 万** |
| 合肥 | 市区约 500 万 | **1000.2 万** |
| 长春 | 市区约 450 万 | **908.5 万** |
| 石家庄 | 市区约 500 万 | **1124.7 万** |

哈尔滨那条查出了来源：550 万接近该市 **2018 年**市辖区（不含五县）人口 550.9 万，
被误标成「都会区」并一直沿用。重庆「中心城区约1000万」同理，是 2022 年主城九区的旧数
（1047.76 万）—— 官方公报只有「全市 3190 万」与「主城都市区 21 区县 2183 万」两档，
根本没有「中心城区」这一档。

**修法**：统一改为公报口径「年末全市常住人口」，重庆额外并列「主城都市区」。
天津、石家庄、桂林原本想强调城区，但查不到可靠的官方分区数据 —— 按红线**不补数字**，
直接换成全市口径，把「公报未单列市区口径」写进注释。

**教训**：核数字之前先核**口径存不存在**。一个查不到官方定义的口径，后面跟的数字
再精确也没有意义 —— 而且它比缺年份更隐蔽，因为读起来完全像个正常的统计量。

**第二个实例（2026-09-08，纽卡斯尔）**：正文写「泰恩赛德城区约 80 万人」。ONS 2011 年
普查确实把纽卡斯尔、盖茨黑德、桑德兰等连成一个 *Tyneside* 建成区（约 77–83 万），但
**2021 年普查改版建成区分类后，*Tyneside* 这个合并统计单元不再存在** —— 现在纽卡斯尔
（286,445）、盖茨黑德（115,280）、桑德兰（168,315）、泰恩茅斯（60,605）各自独立。
原文八成来自维基上沿用旧口径的说法。

这一条与中国那批的区别值得记住：中国那批是**口径从来就不存在**（「都会区人口」不是
官方称谓），纽卡斯尔这条是**口径曾经存在、后来被官方取消**。两种都不能靠"换个新数字"
解决。

**特别注意不要自造合成口径**：把几个建成区相加凑回旧口径的 80 万，等于发布一个 ONS
从未公布过的数。改成并列写两个独立建成区、并说明二者相连但统计上分列，才是诚实的做法。

**第三、第四个实例（2026-09-08）**：

- **澳门「2024 年人口约 71 万」** —— DSEC 只有两档官方口径：总人口（含外地雇员及外地
  学生）与本地人口（剔除两者）。2024 年末分别是 68.83 万与 56.87 万，**71 万两个都对不上**，
  查无来源，应视为误植。同条目的 `identity` 段已是 2026 Q2 的 68.65 万，两段互相矛盾。
- **保定「常住人口约 905 万（2024 年末）」（2026-09-08）** —— 数字本身没错，
  错在**没写是哪个口径**。保定市公报原文并列两句：「年末全市（含定州）常住人口 1008.61 万人。
  年末全市（不含定州）常住人口 900.07 万人」——定州是河北省直管县级市、由保定代管，
  两个口径长期并存。identity 写不含定州的数、howItWorks 写含定州的数，谁都没说明，
  同一个城市里就出现两个差一百多万又互不解释的人口。这是继韩国「住民登录 vs 统计厅推算」、
  智利「普查计数 vs 调节后」之后的**第三例「一地两个并存官方口径未加说明」**。
  修法与前两例一致：**两个都写出来**。
- **台北「与新北、基隆连成约 700 万人的大台北都会区，占全岛人口约三分之一」** ——
  一句话里踩了三样：① 台湾官方统计**没有「都会区」这个法定口径**，「大台北」是媒体与
  学界的俗称；② 三市户籍人口相加实为约 682 万，不是 700 万；③ 682 万 / 2,324 万 ≈ **29.4%**，
  是「近三成」而不是三分之一。修法是把口径注明为非官方、数字改准、比例重算。

### C6-c-2 引的是普查数，但**普查数本身抄错了**（2026-09-08 发现）

刷新中国批 4 时冒出来一类之前没见过的：`identity` 段写「2020 年人口普查常住人口约 X 万」，
**这个 X 根本不是七普的数**，而同一条目 `howItWorks` 段的同年份数字是对的。

| 城市 | identity 写的 | 2020 年七普实际 |
|---|---|---|
| 凯里 | 约 54 万 | **709,057**（约 71 万） |
| 吉林市 | 约 401 万 | **3,623,713**（约 362 万） |
| 呼伦贝尔 | 约 211 万 | **2,242,875**（约 224 万） |
| 中卫 | 约 102 万 | **1,067,336**（约 107 万） |

十条里四条，比例不低。看起来是把**户籍人口或某个非普查年份的估算数**误标成了普查数
（吉林市的 401 万接近其 2019 年末户籍人口 411 万，凯里的 54 万像是 2019 年的旧数）。

**呼伦贝尔那条最阴险**：错写的 211 万，恰好非常接近 2025 年末的真实数 211.9 万 ——
一个错的旧数正好落在今天的真值附近，只看数字量级根本发现不了，必须去核**那个年份的
那个口径**到底是多少。

**教训**：带口径标注的数字（「2020 年人口普查」）读起来比裸数字可信，但标注本身也可能
是编的。核实时要把「年份 + 口径 + 数值」当成一个整体去对，不能因为句子写了口径就假定
它对上了。

**同一天还发现一处行政级别写错**：武夷山 `identity`（中文）写「武夷山市是福建省地级市」，
实际是**南平市代管的县级市**（1989 年由崇安县改设）。同条目的 `howItWorks` 段写对了，
**英文 identity 也写对了（county-level city）—— 三处写法两对一错**。分段成文、中英分别
成文，错误就会这样零散地藏在其中一处。

**再记两个「看起来合理但经查证有误」的陷阱**（本轮子代理主动拒绝采用，值得学）：

- 网传「景洪 2025 年末 69.47 万，比上年增 2.9 万」——只见于一个证书已过期的行政区划
  聚合站，而该市近年常规增量是 0.19 万—0.3 万，**单年增 2.9 万不合常理**，判为不可靠。
- 网传「喀什 70.69 万（2024 年）」——查证后实为 **2018 年末**数据被搜索引擎摘要错标成
  2024 年。

两条的共同点：数字量级都合理，只有对照该地历年变化幅度、或点开原页看落款年份才能识破。

**C6-c-3 把「推算 / 展望值」当成了实测值，还标上普查年份**（2026-09-08，日本批）：

- 高山市 `identity` 写「人口约8.2万（**2025年**）」—— 2025 年国勢調査速報值实为
  **79,355 人**（较 2020 年减少 6.0%）。8.2 万很可能引的是高山市自己的**人口ビジョン**
  （人口展望文件）里对 2025 年的**预测值**。
- 松本市写「人口约23.6万（**2025年**）」—— 实测 **232,347 人**（−3.65%）。同一模式。

**这比缺年份更危险**：句子里那个年份看起来像是「已经核到最新一期」的标志，实际上是把
一份规划文件里的预测数当成了统计实测数。判断线索是**该年份是普查年、而数字与普查
速报对不上**；遇到标着普查年（末位 0/5）的日本城市人口，一定要去核 e-Stat 或都道府县
公布的速報集計，不能只看数字量级是否合理。

**「查得到公报存在、但拿不到数字」的三种形态**（都不是我们没查，是取不到）：

1. **网站反爬** —— 黄山 huangshan.gov.cn 全站返回 412 / Environment Checking；
   哈尔滨那条 PDF 曾指向内网 IP（后来换官网另一入口解决了）。
2. **公报正文就是图片** —— 遵义、汉中的官方公报页面是纯图片格式，机器提不出文字；
   三亚的公报本体也是图片版。**这一类连 OCR 之外没有别的办法**。
3. **证书失效 / DNS 解析失败** —— 北海、大连、温州、扬州、镇江都遇到过；
   襄阳、上饶的政府页也是证书报错，只能退到二级转载。
4. **列表页抓不全** —— 镇江市统计局的公报列表页抓下来只有 2017–2019 年的旧条目
   （疑为分页 / JS 加载），最新一期明明该发了却定位不到。这一类**要人工翻页**，
   不能因为"搜不到"就断定"没发布"。

四种情况的共同处理：**正文停在能核实的那一期并写明原因**，开 issue 跟踪，
**绝不用一个没核到的数字顶上**。

**「查得到公报、但公报里就是没有常住人口」也有三种成因**，别混为一谈：

1. **该级别公报的固定格式里就没有这一节** —— 喀什市、和田市、巴楚县、伊宁市
   （2024、2025 两期全文核对）均如此。南疆县级行政区普遍是这个格式。
2. **那一年只公布户籍人口** —— 齐齐哈尔 2025 年公报只有户籍 493.6 万；宜宾 2025 年公报起
   同样只给户籍总人口 543.5 万（第六、第七例）。**户籍 ≠ 常住，不能拿来顶替**，
   儋州就是这么错的（见下）。
3. **那一版公报干脆没有人口章节** —— 阿勒泰市 2024 年公报全文转换后确认通篇没有人口段落；
   南通 2025 年公报把第十二章标题从「人口、人民生活和社会保障」改成「人民生活和社会保障」，
   常住人口与城镇化率整章删除（第一、第二例）。既不是格式所限也不是数据缺失，就是这一版没写。

三种成因下，**停在 2020 年七普数并标注为普查数都是正确处理**，不需要改，
也不该在下一轮被 `C6d` 当成"过期"再改错一次 —— 所以这些条目必须留 sources 注释写明原因。

### C6-c-4 口径的四种「不能这样用」（2026-09-08，比利时 + 丹麦批）

C6-c 原来只有一条：**口径先于数字，先确认这个口径在该国官方统计里存不存在**。
比利时 9 城 + 丹麦 9 城这一批把它拆成了四种互不相同的形态，混在一起会看不出各自的防线。

**① 口径存在，但已经停止发布 —— 数字还在被当成现行值用。**
根特「都会区约 56 万」、列日「由 52 个市镇组成的都会区约 75 万」，出自比利时旧的
`grootstedelijk gebied`（大都市区）统计口径，**末次数据是 2008 年**（根特 594,582、
列日 749,110），此后近二十年再没发布过。这不是数字过期（C6-d）——过期的意思是
「有新一期，我们引的是旧的」；这里是**这套口径本身被废弃了，永远不会有新一期**。
防线：引用一个口径时要顺手确认**它最近一期是什么时候发布的**，只看数字有没有来源不够。

**② 口径在这个国家根本不存在 —— 那个数是编出来的。**
哥本哈根「都会区约 210 万」：丹麦统计局只发两档并存口径，`kommune`（市镇）与
`byområde`（城区/建成区），**没有「都会区」这一级**。最接近的行政单位首都大区
（Region Hovedstaden）2026 年三季度是 194.9 万，也够不到 210 万，而且它含博恩霍尔姆岛，
本来就不是通勤都会区的合理近似。同一形状此前已见于台北「大台北都会区约 700 万」。
奥胡斯「东日德兰的都会区约 140 万」形状相同，但暂时找不到可靠替代值，**已记 unknown 不改**
（[#218](https://github.com/AudreyYZY/skyterrain/issues/218)）。

**③ 数字是对的，标签是错的。**
赫尔辛格「2026 年**人口**约 4.8 万」、罗斯基勒「2026 年**人口**约 5.4 万」——
48,450 与 53,897 都是 `byområde`（城区）口径的准确数字、年份也是最新的，
却都被写成了「市镇」人口；两地市镇实际是 64,460 与 93,142，差出 1.6 万与 4 万。
**年份对、数字对、来源对，只有那两个字错了** —— 这类最难被发现，因为逐项核「有没有年份、
有没有来源、数字对不对」全都通过。防线只能是：**两档并存的国家，逐句写明是哪一档**。
（丹麦、瑞典、挪威、芬兰都属于这一类，比利时的市镇/大区也是。）

**④ 一个编出来的分母，会连带把结论也带偏。**
哥本哈根那段的结尾写「初来的人最容易犯的错，是把哥本哈根市当作整座城，
**而它只占都会区人口的三分之一**」—— 三分之一是拿 67 万除那个并不存在的 210 万算的。
换成真实的连绵建成区 141 万，67 万是**将近一半**，那句「三分之一」也跟着错。
**删掉一个错口径时，必须回头看有没有别的句子拿它当分母** —— 这一条在补丁清单里差点漏掉。

**⑤ 顺带记一条会影响下一轮的发布风险**：丹麦统计局在《Byopgørelsen 1. januar 2026》里
明确写了「der er ikke planlagt yderligere opgørelser」——`byområde` 系列因底层地名数据库
（Klimadatastyrelsen「Danske Stednavne」）停止更新而**暂无后续发布计划**。
丹麦所有城市条目的城区人口都建立在这套口径上，下一轮核实要先确认它是否恢复；
若不恢复，这些数字会整体变成「已知最新一期、但口径已冻结」，届时要进
`docs/claims-stale-exempt.json` 而不是被 C6d 逼着改。

**本批同时确认的 C6i（同条目两段人口打架）实例**：奥尔堡 identity 写「约 14 万」，
**市镇 22.6 万与城区 12.3 万两个官方口径都够不着** —— 这是 `check:claims` 的 C6i 报出来的
两条之一，核实确认属实。同形状的还有斯帕（identity 1.1 万 > howItWorks 1 万 > 实际 9,905）、
锡尔克堡（identity 4.6 万 < 本条目自己给的城区 5.3 万）、安特卫普、那慕尔、奥胡斯。
**六座城，同一种错**：identity 与 howItWorks 是分两批写的，写后一批时没有回头看前一批。

### C1-b-2 限定语用错了范围 —— **比不写限定语更糟**（2026-09-08，泰国批）

苏梅岛条目写「苏梅岛是**泰国湾**第二大岛屿」。这句话看起来是模范写法：排名带了地理范围。
可它是错的，而且错得比裸写「第二大岛」更隐蔽：

- 「泰国湾第二大」隐含的比较对象是普吉岛，**而普吉在安达曼海，根本不在泰国湾**；
- 真在泰国湾里比，苏梅（约 229 km²）大于象岛（约 217 km²），**是最大的那个，不是第二**；
- 同条目的 `howItWorks` 写的才对：「泰国第二大岛」（普吉 514 > 苏梅 229 > 象岛 217）。

**裸写「第二大」的句子会被 `C1b` 报出来，写了范围的反而放行** —— 限定语在脚本眼里是
正确写法的标志，所以范围写错时脚本是帮凶。**范围一旦写出来，就必须真的核过那个范围里的名次**，
不能只核「这个东西排第几」。

**同一批还撞到一个反过来的例子，值得学**：呵叻条目写「那空叻差是玛是泰国面积最大的府」，
而仓库里北碧条目写「北碧府是泰国第三大府」—— 这两句共同蕴含的排序（清迈 > 呵叻 > 北碧）
和第一句直接矛盾。**同一个仓库里两处排名互相矛盾，本身就是不需要联网也能发现的信号**；
实际情况是清迈 22,311 km² > 呵叻 20,736 > 北碧 19,482，呵叻是第二不是第一。

**两套并行口径也在这一批出现**（C6-c 的老形状，新国家）：泰国的人口有
**DOPA 登记**（内政部地方行政厅，户籍口径）与 **NSO 普查**（实际居住）两套，
曼谷登记 542 万、NSO 六省规划区普查 1,522 万，差三倍。原 identity 写的「1050 万」
和「都会区 1700 万」两个数**哪一套都对不上、也查不到来源**。度假城市差得更悬殊
（芭提雅登记 12 万、估计实住 50 万量级），所以泰国条目一律写明「登记人口」。

### C3-b 隆升 / 演化的**时序**被压成一次性事件（2026-09-08，中国主干地形批）

青藏高原条目写「地壳被压得极厚……**整体抬升**」。这是一句已经被推翻的教科书简化：
中科院青藏高原研究所丁林院士团队的综述给出的是**分阶段、差异性隆升** ——
约 9500 万年前冈底斯先隆出海面 → 约 5500–4500 万年前冈底斯造山带升至约 4500 m →
约 4500–4000 万年前分水岭山脉升至约 5000 m（「两山夹一盆」）→ 约 4000–3000 万年前中央谷地抬升 →
约 2500–1500 万年前喜马拉雅与昆仑才接近现代高度。

**「整体」「一次」「同时」这类词是这一类的标志词**：地质过程横跨几千万年、各部分先后不一，
写成一次性事件既不对，也让「为什么这里高那里低」这个问题失去答案。核地形讲解时，
凡出现隆升、成因、演化的句子，都要去问一句**「这是同时发生的吗」**。

### 零争议红线：自查发现的两处，**修法是删不是改对**（2026-09-08）

中国主干地形批里发现两处踩红线，都不是外部来源指出的，是按 CLAUDE.md 的红线逐条自查出来的：

1. **青藏高原 `history`「1951 年西藏和平解放」** —— 关于当代主权归属的政治表述。
   同段的公路、铁路通车年份是中性工程事实，保留；这一句删掉。
2. **长白山 `history`「1962 年边界条约……天池略多于一半在中国一侧」** ——
   这句**同时是事实错误**（那份条约把天池约 54.5% 划在朝鲜一侧）。
   但**正确的修法不是把比例改对，而是整句删掉**：红线写明 `history` 段不碰现代政治与领土，
   写「哪一国分到多少」正是那一类。现在只留「天池跨在中国与朝鲜的边界上」这个中性地理事实。

**第 2 条是这一类里最容易走偏的地方**：发现一个数字错了，本能反应是把它改对。
但如果这句话本来就不该写，改对等于把一句违规的话写得更精确。
**先问「这句话该不该在这里」，再问「它对不对」。**

### E3 注释里对「下一期什么时候来」的预判本身写错了（2026-09-08，法国批）

法国 17 个城市条目共用一句样板注释：「这套口径按法律就滞后三年……
**下一版（参照 2024 年）**预计 2026 年 12 月下旬公布、2027-01-01 生效。」
前半句对（INSEE 的 populations de référence 2023 由 2025-12-26 法令确认、2026-01-01 生效，
所以那 8 条被 C6d 报出来的「2023 年人口」**不是落后一期，恰恰是当前唯一在用的一版**）。
**后半句错**：INSEE 正在把发布滞后从三年压到两年，2026 年底那一版**直接参照 2025 年**；
2024 那一档虽会同期发布，官方称之为「空档年」（année blanche）、**不具规制效力**。

这不是内容错误，是**流程错误**：下一轮的人会照着这句注释去找「2024 年那一版」，
找不到就可能以为发布延期、或者退而引用那个没有规制效力的数。
**注释里写「下一期什么时候来」是好习惯（`docs/data-refresh-calendar.md` 就是为此存在的），
但那句预判本身也要核，而且它比数字更容易悄悄过期** —— 数字有 C6d 盯着，预判没有任何脚本盯着。

### C6-j **会变的量不止人口** —— 而脚本只盯着人口（2026-09-08，中国地形批）

`check:claims` 的 `C6` / `C6d` 两条规则里，「易过期量」的正则只匹配**人口**
（`PERISHABLE_ZH` = 常住人口 / 户籍人口 / 居民 …）。当初这么画是有理由的：
面积、海拔、长度基本不随时间变，全都纳进来会把信噪比压垮。
但这一批撞到了两个反例，说明这条前提有洞：

- **青海湖面积**：正文写「面积约 4500 平方公里」，不带年份。可这个湖**自 2004 年起
  连续扩张了二十年** —— 2005 年低点约 4,237 km²，2024-12-20 监测已达 4,650.08 km²。
  更要命的是**同一年里两次监测就差一百多平方公里**（2024-03 发布的是 4,540.98）。
  一个裸数在这里不是「旧」，是**根本没有意义**。
- **盖帕奇冰川面积**（欧洲批）：17 km² 是旧值，2023 年奥地利冰川清查为 14.6 km²，
  而且它和帕斯特采的名次**随时可能翻转**。

**共同点是「这个量正在被某个过程持续改变」** —— 湖在扩张或萎缩、冰川在退缩、
海岸线在淤进或蚀退、沙漠边缘在移动。这类量与人口同类，只是脚本看不见。

**目前没有脚本防线，只能靠写作习惯**：
凡写湖泊 / 冰川 / 冰帽 / 海岸线 / 沙漠边界的面积或长度，**必须带监测时点**，
并且在 `sources` 注释里写明「下一轮回来刷新」。
**正确写法的范例就在同一批里**：鄱阳湖条目写的是「丰水期可达 3000 多平方公里、
枯水期只有几百平方公里」—— 用季节性区间代替单一定数，比补一个年份还稳。

（要把这一类变成脚本，得先解决「怎么区分『青海湖面积』和『四川盆地面积』」——
前者在变、后者不变，而句子形状是一样的。暂时没有好办法，先记在这里。）

### 豁免表与 C6d 的一个重叠（2026-09-08 实测）

大连、泉州、黄山这三条本来要进 `claims-stale-exempt.json`：它们的数字停在 2024 年，
理由是「2025 年公报只公布户籍人口 / 官网反爬取不到」。可写完补丁一跑，
`check:claims` 反过来提示这三条**豁免已经用不上了**。

原因是修正后的句子长这样：

> 2024 年末全市常住人口约 754.4 万（**2025 年**公报只公布户籍人口，常住人口待抽样调查数据发布后更新）

`C6d` 取的是句子里**最大的**年份，而那句解释本身带进了 2025 —— 于是判据认为这句话交代了时点。
**这不是漏洞，恰恰是想要的结果**：读者拿到的是「数字是哪一年的、为什么停在这一年」，
比一个裸年份信息更全。所以正确处理是**把这三条从豁免表里删掉**，
让脚本按句子本身判断。

**留下没用的豁免条目是有害的**：豁免表的作用是「别再来核这一条」，
一条已经不触发规则的豁免只会在将来真的过期时替它挡枪。
`check:claims` 现在会主动把这种「🧹 已经用不上」的条目报出来，跟着删就行。

### C6-c-5 **六个条目共用同一个自造口径**（2026-09-08，中国 15 城批）

`C6-c` 说的是「口径先于数字：先确认这个口径在该国官方统计里存不存在」。
这一批把它推到了极端 —— **福州、济南、长沙、南宁、海口、兰州六个条目，
identity 段全都写着「市区常住人口约 N 百万」**，中英同步，而
**「市区常住人口」根本不是中国官方统计口径**：地级市年度公报只有「全市常住人口」
与「城镇常住人口」两档官方称谓。

六个条目、一个错误，说明它们是**同一批写出来的**，作者当时脑子里有一个「市区人口」的概念，
就一路套了下去。这类错误的特征是：

- **不会被任何单条核实发现** —— 逐条看每一条都「有数字、句式规范」；
- **只有把同一批条目并排看才会显形**；
- 修的时候必须**六条一起改**，改一条留五条比全不改更糟（口径不一致）。

**兰州那条还多踩了一层**：兰州公报里确实有「城区」人口这一档（七普城区约 304 万，
与原文写的「约 300 万」量级接近），但它**不叫「市区常住人口」**。
**一个真实存在的口径被叫错了名字，比纯粹编一个口径更难发现** ——
数字能对上，只有名字是错的。

**防线**：`check:claims` 的 `D1b` 只拦「说了公报未单列市区人口又给出市区人口」这一种自相矛盾，
拦不住「通篇都用一个不存在的口径」。目前只能靠核实时把同一国家的条目**并排看**。

### C6k **「这个国家没有的口径」现在有脚本了**（2026-09-08 建）

`C6-c`（口径先于数字）一直只能靠人核。C6-c-5 那批（六个中国城市共用「市区常住人口」
这个自造口径）说明它必须变成脚本：**逐条核实永远发现不了这种错**，每条单看都
「有数字、句式规范」，只有把同一国家的条目并排看才显形 —— 而「并排看」正是脚本擅长的。

`npm run check:claims` 新增规则 **`C6k`**：按条目所属国家查一张**已核实过的**
「这个国家没有的口径」表（`FAKE_CALIBER`，在 `scripts/check-claims.ts` 里）。

| 国家 | 拦什么 | 依据 |
|---|---|---|
| 中国 | 「市区/中心城区/主城区**常住人口**」 | 地级市年度公报只有「全市常住人口」与「城镇常住人口」两档 |
| 中国 | 「**都会区人口**」 | 「都会区」在中国不是官方统计口径 |
| 丹麦 | 「都会区 + 数字」/「metropolitan area/population + 数字」 | 丹麦统计局只有 kommune 与 byområde 两档 |
| 挪威 | 「市区人口」「都会区 + 数字」/「metro area」 | SSB 只有 kommune（市镇）与 tettsted（城区）两档 |
| 意大利 | 「市区人口」「都会区 + 数字」 | ISTAT 只有 comune 常住人口；该写「大都会市（città metropolitana）」 |
| 新西兰 | 「都会区 + 数字」 | Stats NZ 只有 region / territorial authority / urban area 三档 |
| 日本 | 「市区人口」「都会区 + 数字」 | 総務省按「市区町村」逐一发布，无「市区人口」；都市圏的官方专名是「東京圏」「近畿大都市圏」「中京大都市圏」 |
| 荷兰 | 「都会区 + 数字」「兰斯塔德 + 数字」/「metro area + 数字」 | CBS 约 2016 报告年度起**停止发布** agglomeratie / stadsgewest；兰斯塔德不是按年发布的统计单元 |

**三条设计上的取舍，每一条都是被误报逼出来的**：

1. **判据必须按国家**。同一个词在不同国家的合法性完全不同 ——「都会区」在美国（MSA）、
   日本（都市圏）、葡萄牙、菲律宾都有官方口径，在中国与丹麦则没有。伦敦、里斯本、
   马尼拉、雅加达、温哥华的条目里都有「都会区」，一条不分国家的规则会把它们全报出来。
2. **普查确实会单列市辖区**。「市区约 122 万（2020 年普查口径）」**不是**自造口径 ——
   人口普查按市辖区汇总是有的，不存在的是**年度公报**里的「市区常住人口」。
   所以句子里点明了「普查 / 市辖区」就放过（与 C6d 豁免普查同一个道理：**口径写出来了就不算含糊**）。
   第一版规则没有这条豁免，一跑报出 25 处，其中十几处是这种合法写法。
3. **要求同句里有数字**。「哥本哈根都会区」当作地名说一句「近郊自然水域」不是引用统计口径；
   哥本哈根—马尔默那句「连成跨国的都会区」说的是厄勒海峡两岸的城市群。
   都加进了放行清单（`CALIBER_OK`）。

**表里只写已经核实过的国家**。没核过的不要凭印象往里加 —— 那等于用一条猜测去拦另一条猜测；
每一行都要能指到这份台账里的一个实例。

**建成当天扫出 3 处并清零**，此后是硬防线（基线 0，新写一处就直接失败）：

- **台北 `identity`「都会区人口约七百万」** —— 上一轮**只修了一半**：`howItWorks` 早已改成
  写明「『大台北』不是官方统计口径」并给出三市户籍合计，`identity` 却还留着这个数
  （而且 682 万被写成了七百万）。**同一条口径问题在一个条目里往往出现两次，
  修的时候要把整个条目搜一遍，不能只改报出来的那一处。**
- **奥胡斯「东日德兰的都会区约 140 万人」（中英各一处）** —— 上一轮判 unknown 留着没动，
  这一轮**改判为必须删**。丹麦统计局根本不发布「都会区」，「东日德兰城市带」是区域合作
  组织自定的范围。按项目一贯原则 —— **口径是编的，数字再精确也没意义** ——
  **留着一个来自不存在口径的数字，比暂时缺这句话更糟**。这一条修正了上一轮的判断：
  「拿不准就记 unknown」说的是**不要编一个替代值**，不是「把已知有问题的表述原样留着」。

### C6 的一个盲点：**不带「人口」二字的人口数字整片漏掉**（2026-09-08 补，棘轮 +77）

`C6` / `C6d` 的易过期量正则一直是「**人口 / 居民** 这类词 + 数字」。挪威与意大利那批核实时
撞到一句「米兰……**都会区约 320 万人**」——句子里根本没有「人口」两个字，
于是 `C6` 从来没报过它。补测一扫，**这样的句子有 51 处**（中文），
加上英文侧的 `metro area of about 5.3 million` 一类，**总共让棘轮涨了 77**。

漏掉的都是同一个形状：**口径词直接接数字**。

> 悉尼是澳大利亚最大的城市，新南威尔士州首府，**都会区约 530 万人**。
> 名古屋是爱知县首府，日本中部（中京圈）的中心城市，**都会区约 900 万人**。
> 芝加哥是美国第三大城市……**都会区约 950 万人**。

正则已补第二条分支：`(都会区|城区|市区|市镇|全市|全岛|大区|连绵区|聚合区|建成区|都市圈|首都圈)
+ 数字 + 万人`，英文侧对应 `metro/urban/built-up area + 数字 + million`。
**收得很紧，只认真正的行政/统计口径词打头** —— 不然「每年吸引上百万人」这类访客数会被一起报进来。

**这次棘轮是往上走的（313 → 390），基线照实刷新。** 记在这里是因为它说明了一件事：
**棘轮的数字只反映「规则现在能看见什么」，不反映「内容有多可靠」。**
规则画窄一点，计数就好看一点 —— 所以每次收窄判据（C1a 的时间比较豁免、C1b 的词内口径豁免、
C6k 的普查豁免）都要写清楚理由，每次拓宽也要照实让计数涨上去。
**为了让数字好看而不去补这条分支，才是真正的作弊。**

### C6-c-5 的第二、三例：挪威 8 城与意大利（2026-09-08）

中国那批（六城共用「市区常住人口」）之后，同一形状在挪威与意大利各出现一次，
而且**一次比一次隐蔽**：

**挪威 —— 8 个条目的 identity 全都写着「市区人口」**，而 SSB 只发布 `kommune`（市镇）与
`tettsted`（城区）两档，从来没有「市区」这个称谓。**比中国那批更难发现的地方在于**：
同一个自造标签底下，**背后对应的真实口径并不统一** —— narvik、alta 两条的数字实际是 tettsted，
kristiansand、stavanger、bergen、lillehammer、alesund、bodo 六条大致对应 kommune。
中国那批是「标签和数字一起错」，挪威这批是「**标签本身不存在，但背后的数字有的是对的，
只是没说清是哪一档**」。narvik（1.4 万 vs 2.16 万）与 alta（1.5 万 vs 2.17 万）两条
identity 与 howItWorks 打架，根子正是这个。

**意大利 —— 变体：identity 段系统性地用未经核实的旧数字**。凡是「大都会市」型城市，
identity 都写「都会区约 X 万人」，而这个数字与同条目 howItWorks 里已核实过的
città metropolitana 数字对不上：**巴里 75 万 vs 122 万、卡塔尼亚 78 万 vs 107 万、
卡利亚里 43 万 vs 53 万** —— 三个大都会市条目全中，只有博洛尼亚碰巧两段接近。
罗马则是「市区人口」这个自造口径的又一例（ISTAT 只有 comune 常住人口）。

**卡利亚里还多一层**：`howItWorks` 写「大都会市有 17 个市镇」——**2025 年 6 月 1 日起撒丁
大区改革撤销南撒丁省，把它的 53 个市镇并入，市镇数由 17 增至 70**。
**行政区划改革会让「有几个市镇」这种看起来最稳的数字过期**，与里昂都会区 2024 年两市镇合并
（59 → 58）是同一形状。

**`C6k` 表已加入挪威与意大利的「市区人口」**。「都会区」在这两国暂时没有加进去 ——
奥斯陆、特隆赫姆、特罗姆瑟、米兰、博洛尼亚还在用这个词，数字尚未逐条核实完，
**先核实再入表，不能用一条猜测去拦另一条猜测**。

### C6-c-5 的第四、五例：新西兰与澳大利亚（2026-09-08）

补上 C6 那条「不带『人口』二字的数字」分支之后，澳新条目整片露了出来，**两国的问题不是一回事**：

**新西兰 —— 同一个中文词在四个条目里指了四种东西。** Stats NZ 只有
`region` / `territorial authority` / `urban area` 三档，**没有与美国 MSA 对等的「都会区」**。
可这批条目里「都会区」分别指：奥克兰 = 大区（Auckland Council 统一辖区）；
惠灵顿 = **四个市议会人口相加**（不是官方统计单元）；基督城 = **自造的「市 + 塞尔文 + 怀马卡里里」三区相加**；
达尼丁 = **直接把 territorial authority 辖区人口当成城区人口**（那个辖区约 3,286 km²、
同条目自己写着「比美国罗德岛州还大」，绝大部分是农村，官方城区口径只有约 10.4 万）。
**惠灵顿与基督城的 identity / howItWorks 两段还各自打架。**

**澳大利亚 —— 口径没编错，是整批 identity 忘了同步。**「都会区」在澳大利亚对应 ABS 真实存在的
GCCSA，措辞本身没问题；问题是**六个首府（悉尼/墨尔本/布里斯班/珀斯/阿德莱德/达尔文）的 identity
数字全是旧的**，与同一条目里后写的 `howItWorks`（已查过 2025-06-30 ABS 数据）系统性对不上 ——
布里斯班最明显：identity 写 260 万，howItWorks 自己写着 283 万。
这是「先写 identity、后写 howItWorks 但没回头同步」的批次性遗留，与编造口径是两种病。
纽卡斯尔额外多一层：**它不是首府，ABS 根本没有「Greater Newcastle」这个 GCCSA**，
官方口径是 SUA（Significant Urban Area）——用「都会区」去指 SUA 容易被读成 GCCSA。

**修完之后，`C6k` 表已覆盖五个国家**（中国、丹麦、挪威、意大利、新西兰），全部回到 0。
表里三条判据上的取舍也随之定型：
① **按国家**；② **句子里点明普查/市辖区就放过**；③ **同句里必须有数字**
（「哥本哈根都会区」当地名说一句风景、「连成跨国的都会区」说的是厄勒海峡城市群，都不算）。

**这一轮还确认了一个反复出现的模式**：**同一条口径问题在一个条目里几乎总是出现两次** ——
identity 一次、howItWorks 一次，而且往往只修了一处。台北、都灵、那不勒斯、巴勒莫、基督城
都是这么被 C6k 抓出来的：**修口径问题时要把整个条目搜一遍，不能只改脚本报出来的那一处。**

### C6-c-5 的第六例：日本 —— **自造口径底下的两个数字互相矛盾**（2026-09-09）

日本这批把这一类的机理说清楚了：**为什么自造口径几乎必然导致同条目两段打架**。

総務省統計局按「市区町村」逐一发布人口，**没有「市区人口」这个复合概念**
（「市」与「区」在日本是平行的不同层级，「区」特指政令指定都市下辖的行政区或东京 23 区）；
都市圏有两套官方定义 —— **大都市圏**（1.5% 通勤/通学阈值，官方专名「東京圏」「近畿大都市圏」
「中京大都市圏」）与**都市圏**（10% 阈值，范围小很多）—— **从来没有「都会区」这个词**。

于是：

| 条目 | identity | howItWorks | 官方 |
|---|---|---|---|
| 名古屋 | 都会区约 **900 万** | 中京都会区约 **1,024 万** | 中京大都市圏 919 万（2020 普查） |
| 金泽 | 市区人口约 **45 万** | 人口约 **47 万** | 全市 454,071（2025 速报） |
| 松山 | 约 **49.4 万**（2026 年） | 约 **49 万** | 497,041（2025 速报） |

**一个没有官方定义的词，两次写它的时候就会各自对着不同的东西** ——
名古屋差 124 万、金泽差 2 万、松山两段也对不上。**这就是 C6i（两段打架）与 C6-c-5（自造口径）
其实是同一个病的两个症状。**

**神户是这一批里处理得最典型的一条**：它连一个干净的官方单独口径都没有 ——
学术口径「都市雇用圏」2010 年为 2,431,076；総務省「相対都市圏」约 250 万、「絶対都市圏」约 273 万，
**三个定义三个数字，没有一个叫「都会区」**。按项目规矩：**查不到官方口径就不给这个数字，
只描述通勤关系**，不为了给个数字而套用非官方学术口径冒充官方统计。

**还抓到一个新形状的年份错**：松山写「人口约 49.4 万（**2026 年**）」——
**国势调查每五年一次、年份末位 0/5，根本不存在「2026 年国势调查」**，2026 只是速报的公布年份。
**把公布年当成基准年**，与此前高山市/松本市「拿人口ビジョン的预测值当 2025 年实测值」是同一类：
**那个年份看起来正好像是「已经核到最新一期」的标志**，反而最容易骗过检查。

### 名称本身会变的两类：**族群称谓**与**被政治决定反复改的地名**（2026-09-09，美国批）

数字会过期，**名字也会**，而且是两种完全不同的过期方式：

**① 族群称谓 —— 「哪个词现在还在用」由被称呼的一方决定。**
科罗拉多高原条目中文写「古普韦布洛人（**阿纳萨齐**）」。「Anasazi」是纳瓦霍语词，
本意接近「敌人的祖先」，霍皮等普韦布洛部落自 1990 年代起提出异议，
**梅萨维德等国家公园的官方材料自此改用 Ancestral Puebloan**。
而且这处**英文版本身没有这个括注，只有中文加了** —— 又一次中英不同步。

同批还抓到大峡谷 `history` 把**派尤特（Paiute）写成了犹特（Ute）**，是两个不同的民族。
NPS 官方的 11 个「传统关联部落」名单里有四个派尤特分支、**没有 Ute**。
**写族名要照着管理机构的官方名单核，不能凭发音相近推。**

**② 被政治决定反复改的地名 —— 正文不该替它站队。**
阿拉斯加山脉条目写「北美最高峰迪纳利……（**联邦官方名亦作**麦金利山）」。
事实是：2015 年联邦名由 McKinley 改为 Denali，**2025 年 1 月的行政令与 2 月的内政部命令
又把 GNIS 主名改回 Mount McKinley**（迪纳利国家公园的名称未变，阿拉斯加州政府仍用 Denali）。
原文的主次与 2025 年 2 月起的状态正好相反。

**但正确的修法不是把主次调过来** —— 那样下一次改名又会错，而且「哪个是官方名」这件事
本身已经是政治议题，断言任何一方都可能被读作立场表态。
按零争议红线，改成**两个名字并列、都说明在使用、不断言官方名**。
**这与长白山天池那条是同一条原则的两次应用：先问这句话该不该在这里，再问它对不对。**

### 零争议红线的第三次应用，以及**一次没有采纳的建议**（2026-09-09）

**第三次应用**：台湾岛条目的 `history` 段首句是主权断言、末句写近代治理更迭，
两句都属于 CLAUDE.md 明写的红线（`history` 只写地质史与广泛记载的前现代史，
不碰现代政治、领土、治理更迭）。**修法照旧是删，不是改得更准确** ——
中间三句（三国、隋朝的记载；元朝澎湖巡检司；1885 年建省）是前现代行政史，保留。
同批还删掉了 `seeing` 段的「东北亚地区的最高峰」：「东北亚」的常见定义含俄罗斯远东，
堪察加的火山远高于玉山，这个名次给不出口径。

**一次没有采纳的建议，比采纳的更值得记**：同一轮里，核实方建议按同一条红线删掉大娄山
`history` 段的「1935 年娄山关战斗 + 毛泽东《忆秦娥·娄山关》」。**没有采纳**，理由是：

- 仓库里 **六盘山**（1935 年长征翻越 + 《清平乐·六盘山》）、**吕梁**（晋绥根据地）、
  **大巴山**（多个革命根据地）、**大别山**（鄂豫皖苏区、1947 年挺进大别山）四篇早已是同一写法；
- 上一轮核中国山地时，核实方自己也明确判过这类内容「属历史事实陈述、非评价性表述，
  与项目现有尺度一致」；
- **只删大娄山会让同类内容的尺度不一** —— 那比原样保留更糟；
- 而且这一改动**超出了「核实事实」的范围**：它是一次口径决定，应当一次覆盖全部同类条目，
  不是在某一批里顺手改掉一条。

**这条记在这里，是因为「照抄核实建议去改」本身就是一种失误**（2026-09-08 已经踩过一次：
krabi 那条，核实方说 identity 把府的数当成了镇的，而原文明明写着「府份」）。
**核实结论也要拿原文与仓库现状验一遍**：一条建议是否该采纳，取决于它是不是与全库一致。

**第二次没有采纳（2026-09-09，瑞士地形批）**：核实方建议把伯尔尼纳峰的「4049 米」改成
「4048 米」，依据是德文维基转引 swisstopo 国家地图。查下来两个数字其实是**同一个测量值的
两种取整** —— 国家地图印 4048 米、精测 4048.6 米，而瑞士国家旅游局写 4049 米。
**没有采纳**，理由：① 依据只有一个 3 级来源，而仓库的规矩是「3 级来源不能作为最终数字的
唯一依据」；② 1 米的差落在取整范围内，不是两个互相矛盾的测量。做法是**正文不动、
把两个数字都写进 `sources` 注释**。

**这两次「不采纳」的共同点**：核实方给的都不是假信息，而是**一条不该按它去改的真信息**。
判断一条建议要不要落地，问的不是「它对不对」，而是「按它改完之后，全库会不会比现在更一致、更可核」。

### C6-c-5 第八、第九次 —— 瑞士与冰岛的「市区人口」（2026-09-09）

`C6k` 的表这一轮又扩了两国。老规矩：**只写已经核实过的国家**。

| 国家 | 官方到底有哪几档 | 文案里那个不存在的口径 | 中招条目 |
|---|---|---|---|
| 瑞士 | `Gemeinde / commune`（市镇）· `Kanton`（州）· `Agglomeration`（集聚区，见《Raumgliederungen der Schweiz》） | 「**市区人口**」（6 条）、「**城市连绵区**」（我们自己造的词） | 伯尔尼 / 巴塞尔 / 卢塞恩 / 日内瓦 / 洛桑 / 卢加诺 + 苏黎世 |
| 冰岛 | `sveitarfélag`（市镇）· `byggðakjarni`（城镇聚落）· `höfuðborgarsvæðið`（首都区） | 「**市区人口**」 | 雷克雅未克 |

**这一轮多出来的两件事**：

**① 「不是官方口径」不等于「不能写」**。巴塞尔的三国区、日内瓦的大日内瓦确实有跨境机构在
统计（Regio Basiliensis / GLCT Grand Genève），只是**不是瑞士联邦统计局的数**。做法不是删掉，
而是**写明是谁统计的、哪一年** —— 大日内瓦最近一手数停在 2019-01-01 的 1,025,316，
正文现在照实写「2019 年超过 100 万人」。所以 `C6k` 的瑞士表里**故意没有收「都会区」**：
收了就会把这两条可核的内容一起误伤。

**② 遇到核不到的数，做法是从正文撤下并开 issue，不是换一个看起来更新的数。**
伯尔尼的「城市连绵区约 41 万」核不到一级来源，第三方给的是约 44.3 万 ——
**两个数都没核到，用后者替换前者只是把问题换了个样子**。正文改成给已核实的州人口，
那个集聚区数字撤下并开了 issue（苏黎世的集聚区数、雷克雅未克首都区总数同理，
后者的四个候选数字 244,536 / ~247,000 / 251,900 / 264,056 互相矛盾）。

### C7 因果解释错了，而不是数字错了 —— 而且没有任何脚本能看见（2026-09-09 立类）

| | |
|---|---|
| **症状** | 数字、年代、地名全对，**「这东西是怎么来的」这句话错了** |
| **防线** | **无**。`check:claims` 那一整套盯的是数字、年份、口径、最高级、拼接 —— 一句纯文字的机制解释里没有任何可扫的特征 |
| **还会再犯吗** | **一定会**，而且是所有类型里最难自查的一种 |

首个实例：**内伊湖（lough-neagh）的成因**。原文写的是

> ~~这层沉重的熔岩压在地壳上，加上区域性的拗曲，使中央地区缓慢下沉~~

并且整个 `concept` 段建立在「负荷沉降 / 像被压的弹簧垫」这个模型上，连**判据**都跟着错了 ——
它教读者「看它有没有明显的断层痕迹」，而断层恰恰是主因。英国地质调查局把内伊湖盆地
定性为**受断层控制的构造洼地**（沿一组东北—西南走向的断层），学术文献另有「与北大西洋张裂
相关的拉分盆地」的定性；玄武岩的重量是叠加因素，不是主因。

**为什么这类特别危险**：
① 它读起来非常顺 —— 「厚重的熔岩把地壳压弯了」有画面、有因果、像是真的；
② 它**通不过任何脚本**，只能靠联网核实撞上；
③ 它会**连带把判据一起写错**，而判据正是这个项目 `concept` 段存在的理由 ——
   一个错的判据比一个错的数字传播得更远，因为读者会拿它去看别的地形。

同一批里的正面对照：`aareschlucht`（阿勒峡）的 formation 段写的是「学界至今仍在讨论细节」——
查下来实际情况确实更复杂（基尔谢特岩坎在多个间冰期反复被切出新峡谷又被冰碛填埋，
另有 5 条更古老的旧峡谷）。**用一句留白代替一个漂亮的机制，是对的。**

**能做的只有一条**：`/verify-content` 的 prompt 里现在要求核实方**逐条检查 `formation`
与 `concept` 段的机制表述**，不只是核数字。

### C1a-b 把一句「带保留的、窄口径的」官方话，逐步放宽成断言（2026-09-09）

米湖（`myvatn`）原文：

> ~~正是这些虫子养活了**欧洲**种类最多的一群**水鸟**。~~

冰岛环境署的官方原话是：**「据说**这里的**鸭**的种类比**地球上**任何地方都多」。
三处各放宽了一点：

| 官方 | 我们写的 | 放宽的方向 |
|---|---|---|
| 鸭（duck） | 水鸟（waterbird） | 类别变宽 |
| 全世界 | 欧洲 | 范围**变窄了**，但因此**换了一个不成立的排名** |
| 「据说」（are said to） | 断言 | 语气变硬 |

**每一步单看都像是无害的改写，合起来就成了另一句话。**
注意第二行：范围从「全世界」缩到「欧洲」看着更保守，其实是把一个有出处的说法
换成了一个没出处的说法 —— **保守不等于安全，只有「和来源说的是同一件事」才安全。**

同批第二例：韦斯特曼纳群岛「新熔岩把港口口门**收窄了一半**」——
美国地质调查局的原始记述只说「变窄但没堵死、港口反而更避风」，**没有任何百分比**。
一个听起来很具体的比例，往往正是没人去查的那一处。

### 一批里 14 篇零改动，也要写满 15 条留痕（2026-09-09）

瑞士地形第 2 批 15 篇，最后只改了 1 处（而且那 1 处还不是事实错误，是同一条目两段之间的
枚举对不上：`seeing` 说「四林州湖」、`history` 只列了三个林州，漏了 1332 年加入的琉森）。

**这不是「白跑一趟」**，它换来了三条**明确判定不改**的记录，而这三条恰恰最容易被下一轮
重新翻出来改一遍：

| 条目 | 看起来像错 | 为什么不改 |
|---|---|---|
| `aare-river` | 正文 288 公里 vs 联邦环境局 292 公里 | 差 1.4%，不同测量方法与取点，**同批伯尔尼纳峰 4048/4049 的同型** |
| `ruinaulta` | 正文「约一万年前」vs 最新测年约 9300–9500 年前 | 科普与学术两个精度层级的落差，瑞士旅游局官方页至今仍用「10,000 years ago」 |
| `rhine-falls` | 「按水量和宽度的组合算，欧洲最大的瀑布之一」 | 这个限定**准确且必要** —— 与冰岛黛提瀑布是两个口径，两个条目的写法互相印证、不打架 |

还有一条留了 `unknown`：`creux-du-van` 的「不是冰川冰斗、是泉源侵蚀」——
法语资料提到末次冰期末凹地末端曾有小型冰川、以冻融的机械作用参与塑造崖壁，
与正文完全排除冰川角色存在张力；但可查到的都是 3 级转述，**没有一手地质文献能一锤定音**，
所以原样保留、记下待办，**没有换成另一个同样没核实的说法**。

**「本轮无需改动」是一条结论，不是一次空转** —— 它的价值全在于被写进注释里，
下一轮才不会重新派工、也不会把已经判过的东西再改一遍。

### 两个来源直接打架的时候（2026-09-09）

杰古沙龙冰河湖的深度：冰岛国家自然历史研究所（官方，1 级）给 **248 米**，
英文维基引 2009 年《晨报》（Morgunblaðið）的报道给 **284 米**。差 36 米，
**这不是取整误差，是两个来源互相矛盾**。

处理：**取 1 级，并把冲突本身写进注释** —— 不写进去的话，下一轮碰到那个 284 的人
会以为我们漏了更新，再改一次。分级的意义正在这种时候：不是「哪个数字更新」，
而是「哪个来源更接近发布方」。

同一条目的**面积**则相反：二三级来源在 18–27 平方公里之间分歧，**冰岛官方根本没有发布过
带年份的面积数**。这种情况不选任何一个，改成区间 +「还在随冰舌后退继续变大」。

### C8 「海拔」也会过期 —— 而且是两种不同的方式（2026-09-09 立类）

同一轮的两条，形状一模一样：**一个听起来最不像会变的量，其实每隔一两年就有新值。**

| 条目 | 原文 | 实际 |
|---|---|---|
| `jotunheimen` 格利特峰 | 约 2465 米 | 那是**峰顶冰帽还在时**（2008 年含冰厚约 10–15 米）的数；冰帽 2022 年夏大幅消融、**2023 年 9 月完全消失**，现行裸岩高度 **2452 米** |
| `french-alps` 勃朗峰 | 约 4806 米 | 峰顶是积雪，**每两年由上萨瓦省的专业测绘师实测一次**；2023-09-05 测得 **4805.59 米**，比 2021 年少 2.22 米 |

两条的区别值得分清：**格利特峰是真的错了**（少了 13 米，而且那场「挪威最高峰之争」正是因为冰帽没了才落幕）；
**勃朗峰在取整范围内、数字不算错**，问题是它没有年份 —— 读者会把一个每两年公布新值的量当成恒定值。

同批第三例是同一类的另一种：`dune-du-pilat` 皮拉沙丘，**每年**都有官方新值
（2025 年 101.7 米、2024 年 101 米、2023 年 103 米、2017 年峰值 110.5 米）。

**处理办法这一轮凑齐了三条路**，按可得性从高到低：
① **有官方年度值** → 带年份写，并给出波动范围（皮拉沙丘）；
② **只有区间** → 写区间，不写单一值（冰海冰川的厚度「各处差别很大，不宜给单一数字」）；
③ **不写数字** → 只写机制（英国 `the-fens` 的泥炭氧化沉降，全篇没有一个下沉量，因此永不过期）。

### 「一个制度诞生的年份」不等于「某个对象被纳入这个制度的年份」（2026-09-09）

卡马格 `history` 段原文：

> ~~1971 年列入拉姆萨尔湿地名录 —— 是全球最早一批受国际公约保护的湿地之一~~

**1971 是《拉姆萨尔公约》本身在伊朗签署的年份。** 法国 1986-10-01 才加入公约，
卡马格（编号 346）**1986-12-01** 才正式列入 —— 比公约诞生晚了 15 年，
「全球最早一批」这个附带的结论也就跟着塌了。

**这个形状在遗产、公约、名录类内容里会反复出现**：UNESCO 某个类别设立的年份、
某项公约生效的年份、某个名录开始编制的年份 —— 都很容易被写成「这个地方被列入的年份」。
判据很简单：**问一句「这一年发生的事，主语是这个地方，还是那个制度？」**

同一轮里还有一个近亲：`chaine-des-puys` 把**帕文火山口**当成了普伊山链最年轻的一次喷发 ——
帕文属于**多尔山火山群**，只是喷发时间紧随其后。**「时间上挨着」被读成了「属于同一个东西」**，
而这个错在同一条目的 `seeing` 与 `observation` 段**各写了一次**。

### 把两层嵌套压成一层（2026-09-09）

挪威两条峡湾，同一形状：

- `geirangerfjord` 写「是**斯托尔峡湾**的一条支汊」—— 实际是「斯托尔峡湾 → **宗尼尔斯峡湾** → 盖朗厄尔峡湾」三级；
- `naeroyfjord` 写「是**松恩峡湾**最里面的一条支汊」—— 实际是「松恩峡湾 → **奥兰峡湾** → 纳柔依峡湾」三级，
  而且 `seeing` 与 `observation` **两段各写了一次**。

两条都不是「说错了归属」，是**把中间那一级省掉了** —— 单看每一句都说得通，
只有把水系摊开才会发现少了一层。法国的 `massif-central` 是同一形状的时间版：
坎塔尔（中新世晚期，约 1300 万年前）被和桑西、普伊火山群一起塞进了「上新世到几千年前」这个窗口，
**三件事被压进了同一个时间窗**，坎塔尔差了约 800 万年。

**共同的诱因是「读起来更顺」**：省掉中间一级、把几件事合成一句，都会让句子更短、更好念 ——
而这个项目的正文是要被 TTS 念出来的，简化的动机一直都在。

### 一个真数字，用在了比它大得多的对象上（2026-09-09）

埃特勒塔 `formation` 段：「整段崖壁平均每年后退约 20 厘米」。

这个数字是真的 —— 但它是**塞纳滨海省沿岸白垩崖的区域平均值**（报道只写「据当局称」、没点名机构），
不是埃特勒塔本身的监测数据。反过来还有资料指出埃特勒塔本地岩性底部更致密、更抗蚀，
退缩慢于迪耶普附近的科多勒、克里埃勒（那里达每年 20–40 厘米）。

**这与苏梅岛「泰国湾第二大岛」拿安达曼海的普吉去比是同一类错**：数字或事实本身没造假，
错的是**它描述的对象范围**。正文现在如实写成「查不到本地专门监测数据 —— 区域平均约每年 20 厘米，
而本地岩性更致密、通常慢于这个平均值」。

**第三例（2026-09-09，法国第 2 批）**：朗德「1949 年一场大火烧掉**约五分之一**的森林」——
那场火实际烧毁约 5.2 万公顷，占松林总面积（约 100 万–140 万公顷）的 **3.7%–5%**。
「近五分之一」这个比例真正对应的是 **1937–1949 年累计火灾**（超 45 万公顷、约占森林四成）——
**单次事件被安上了累计数据的比例**。

三例的共同点：**数字都是真的，错的是它所描述的范围** —— 一段崖壁 vs 一个省的海岸、
一座岛 vs 另一片海、一场火 vs 十二年的总和。**核实时不能只问「这个数对不对」，
要问「这个数说的是不是正文说的那个东西」。**

### D-redline 零争议红线被踩了 —— 六处，而且一半是全库扫描才发现的（2026-09-10）

这是这份台账里第一次**由核实方直接报出「你踩线了」**，也是第一次**在同一轮里连续发现六处**。

| 条目 | 段 | 原文 | 处理 |
|---|---|---|---|
| `cheorwon-lava-plateau` | history | 「这一区域也是**朝鲜战争期间军事活动**的历史地点之一」 | **删句** |
| `haean-basin` | seeing | 「因形似大碗而被**朝鲜战争期间的联合国军**称为 Punchbowl」 | 删掉战史归因，只留「俗称 Punchbowl」 |
| `haean-basin` | history | 「盆地北部邻近**朝鲜战争期间形成的军事分界线**……别称即源自**战地记录**」 | **整句换成地貌与生境事实** |
| `haean-basin` | distinguish | 「都地处**军事分界线附近**的江原道山地」 | 改成「江原道北部的山地」 |
| `sokcho`（城市） | identity · howItWorks · culture | 「与**军事分界线**相距不远」「1945 年划界时它在**北纬 38 度**以北，1951 年由韩国军队占领，1953 年**停战**后归韩国」「北面是高城与**非军事区**」「一座**边境城市**」 | 四处全改，保留阿爸村、渡船、鱼糕等可核实的生活事实 |
| `incheon`（城市） | identity | 「1950 年 9 月的**仁川登陆是朝鲜战争的转折点**」 | **删句** |

**三条教训：**

**① 红线不只管 `history` 段。** 六处里有四处在 `seeing`、`distinguish`、`identity`、`culture` 段。
写红线规则时脑子里想的是「历史那一段」，实际它适用于任何一句可能读作立场表态的话。

**② 「派一批去核」和「把这一类在全库搜一遍」是两件事。**
核实方只看它那一批的 14 个地形条目，报出了 `cheorwon` 与 `haean-basin`；
**`sokcho` 与 `incheon` 是我随后对全库跑
`朝鲜战争 / Korean War / 军事分界线 / Military Demarcation / 非军事区 / DMZ / 38 度 / 停战`
的正则扫描扫出来的** —— 它们在城市文件里，根本不在那一批的范围内。
这与上一轮 AONB 那次（写下待办却没执行）是同一件事的两面：**待办要当场做，范围要按「这一类」而不是「这一批」划。**

**③ 删，不勉强补。** `haean-basin` 的 `history` 段整句删掉之后没有硬补一段新历史，
换成了盆底农田、山脊围合、人为活动受限带来的生境保存这些可核实的事实；
`sokcho` 也只是不再交代阿爸村的成因，渡船与鱼糕照写。**宁可少说一层。**

**一次没有跟着改的**（记在这里，免得下一轮当成漏网）：越南 `dong-hoi` 提到「1954–1975 年的
南北分界（非军事区）和永牧地道」、`ho-chi-minh-city` 提到「越战时期的历史遗迹」。
**判断是不改**：越南已经统一、这些是越南官方运营的挂牌景点，正文只作事实陈述、没有任何评价，
而且把永牧地道从洞海的攻略里删掉会让内容对读者更没用。
**朝鲜半岛那几处不同的地方在于：那是一条至今仍在的军事边界**，而且原文里还有「转折点」这样的评价词。
这条界线画在**「是否涉及一个仍在持续的对立状态、以及有没有评价性表述」**上，不是画在「有没有出现战争二字」上。

#### 第七、八处：不涉及战争，涉及的是**对一国内部城市的价值评价**（2026-09-10，土耳其城市批）

> ~~伊兹密尔……因**相对世俗开放的城市氛围**与滨海科尔顿长廊而被称为「爱琴海明珠」~~（`identity`）
> ~~伊兹密尔是土耳其**世俗化程度较高的城市之一**，衣着相对自由~~（`culture`）

前六处都带着战争、边界、军事管制这类显眼的词，扫描能扫到。**这两处一个这样的词都没有。**
它踩的是另一条：拿一个国家内部的不同城市，在**世俗／宗教**这条轴上做比较评价 ——
这在土耳其正是最有政治分量的一条轴。措辞越平和（「相对」「之一」），越像在陈述事实。

**同一个判断在一个条目里写了两遍**（`identity` 与 `culture`，中英共四处），
这又是教训 ② 的复现：**发现一处之后要在这个条目里、这一类里各搜一遍，而不是改掉报上来的那一处就走。**

**处理**：换成不带评价的城市事实（滨海长廊、度假与商贸氛围、日常衣着以休闲为主），
清真寺礼仪那半句照留 —— 那是给读者的实用信息，不是对城市的评价。

**对照组，本轮判定不改的**：科尼亚 `identity` 的「因苏菲派诗人鲁米与旋转苦行僧传统闻名，
是土耳其重要的宗教文化中心」。这句写的是**这座城市有什么**（一个人、一个传统、一处圣地），
不是**它比别的城市更怎么样**。**红线卡的是比较与评价，不是「宗教」这个话题本身** ——
和越南那两处一样，界线画在表述方式上，不画在关键词上。

### 把一个框架写成无例外的铁律，而同一篇的另一段恰好举了那个例外（2026-09-09）

**同一条目的 `observation` 段把朗伊托托岛当作这个火山场最完整的范例来写**，
而同行评议论文（Needham, Lindsay, Smith et al., *GSA Bulletin*）用沉积物碳十四定年确认
**朗伊托托至少有两期相隔近五十年、岩浆成分也不同的喷发** —— 它正是「单成因」定义公认的疑难案例。

**③ 荷兰是「口径已停止发布」的第二例，而且它比比利时那次更彻底。**

**那个数其实就是 gemeente 人口本身、只是套错了标签** —— 与中国的「市区常住人口」同一形状：
**口径名是编的，数字反倒是对的**。

### C6i-b：两段都点名「都会区」，数字却对不上（2026-09-09 加）

补完提取器之后还是抓不到温尼伯 —— 因为 **C6i 主轨是有意只比「全市档」的**：
`CROSS_SUB_ZH` 里明明白白列着「都会区」，带子口径的数字一律被 `nearSub` 排除。
**这个设计是对的**（拿都会区的数去和市的数比会满屏误报），但它留下一个盲区：
**两段都写「都会区」、数字却对不上**，主轨看不见。

温尼伯正是这么漏掉的：identity 写「**都会区**约 85 万」，howItWorks 写
「市域约 85 万、**都会区**约 95 万」——85 万其实是 CSD（市镇）的数被贴上了都会区的标签，
**两个数字都是真的，错的是标签**。卡尔加里（161 万 vs 184 万）同型。

于是另开一条轨：**只在两段都点名同一档口径时比，容差 5%**（都指同一个东西，
就没有「一段取整、一段精确」的余地了）。取值用的是**紧跟在口径词之后**的那个数字 ——
同一句里往往还有市域人口，取错就白做。

**建成当天扫出 4 处，全部是真的**：奥兰多（2.96M vs 2.7M）、亚特兰大（over 6M vs 6.4M）、
圣约翰斯（「a bit over 200,000」vs 243,000）、巴黎（13M vs 12M）。
**四处全在英文侧** —— 又一次印证中英是分开写的、错误也各自独立。

**四条逐条核完之后（2026-09-09），分出三种完全不同的病因** —— 这一点比「扫出 4 处」更重要，
因为**同一条规则报出来的东西，修法可以完全不一样**：

| 条目 | 病因 | 修法 |
|---|---|---|
| 奥兰多 | **英文单侧遗留**：中文两段上一轮已统一到 296 万，英文 howItWorks 还停在旧的 Wikipedia 信息框数 | 只改英文一句 |
| 亚特兰大 | **两段都旧、都没年份**：「超过 600 万」与「6.4 million」都不是最新一期 | 中英四段统一到 Census Vintage 2025 的 MSA 648 万并标年份，顺带点出更大一档 CSA 743 万 |
| 圣约翰斯 | **一段精确、一段模糊**：howItWorks 的 243,000 是对的，identity 的「20 多万」比它低 17.7% | 把模糊的那段改成精确值 —— **模糊表述也会构成冲突** |
| 巴黎 | **两个数字都是真的，冲突的是标签**：13M 是 INSEE 城市吸引区、12M 是法兰西岛大区，同一篇文章用「都会区 / metropolitan area」一个词指了两个不同的官方口径 | 两段都改，各自点名口径 |

**巴黎这一条要单独记**：法国一地有五档口径，数字从 210 万到 1332 万横跨六倍 ——
市镇 `commune` 2,103,778 / 城市单元 `unité urbaine` 11,013,774 /
**城市吸引区 `aire d'attraction des villes` 13,320,752**（2020 版划定，最接近国际语境说的
"Paris metro area"）/ 行政大区 `région Île-de-France` 12,463,067 /
**行政建制** `Métropole du Grand Paris` 7,142,540（2016 年设立，131 市镇，**不是统计口径**），
均为 2023 年参照人口。仓库此前已经在尼斯条目上踩过一次（引了已停用的旧 `aire urbaine`）。

**正文说「都会区 / metropolitan area」一律指 aire d'attraction；行政大区一律用
「法兰西岛大区」专名，不套用「都会区」这个词。**

### 一条防线可以被「合规的写法」绕过去 —— 语序（2026-09-09）

改完巴黎之后 `C6i-b` **还在报**，而且报的正是我刚写下的那句。原因不是数字错了，
是**语序**：我把口径澄清写成了否定式、放在数字前面 ——

> ~~而法兰西岛大区是一个行政大区、口径不同于统计意义上的**都会区，约 1246 万人**~~

规则取的是「紧跟在口径词之后的那个数字」，于是它看到的是「都会区 → 1246 万」，
和 identity 的 1332 万一比，照报不误。**规则没有错，是这句话确实可以被误读成那样。**
改成把澄清放在数字之后，并在同一段里正面写出真正的都会区数字：

> 而法兰西岛大区约 1246 万人（2023 年）——它是一个行政大区，与统计意义上的都会区不是一回事；
> 按 INSEE 城市吸引区口径，**巴黎的都会区约 1332 万人**（2023 年）

英文侧同型：`a metropolitan area — INSEE's aire d'attraction des villes — of about 13.3 million`
里，口径名插在词与数字之间超过 30 个字符，**规则干脆取不到值、这一段静默地退出了比较**。
改成 `a metropolitan area of about 13.3 million on INSEE's aire d'attraction des villes definition`。

**两个方向的教训各一条**：
① 用否定式澄清口径（「这不是都会区」）在正则眼里和肯定式没有区别 —— **澄清要放在数字之后**；
② 把限定语塞在口径词和数字中间，会让规则**取不到值而不是报错** ——
   *一段悄悄退出比较*比*报一个假阳性*更危险，因为屏幕上什么都不会出现。

### 一个新的自检：中英两侧同单位数字对不上（2026-09-10 立类并加脚本 `check:zhen`）

`romsdalen` 的中文写巨魔墙岩壁「约 1000 米」，英文写 about 1,100 m。

**上一轮已经查明这里有两个值、还把冲突写进了注释**（「SNL 给约 1000，英文维基给 1100」），
然后 —— 中文侧挑了一个，英文侧挑了另一个。**不是没查，是查完之后没把结论同步到两侧。**

中英是分开写的，所以这一类天然容易发生；而人核实时是**按语言**读的，除非特意并排，否则看不见。
这正是脚本擅长的形状：**机械、精确、无歧义**。`npm run check:zhen` 比同一条目同一字段里
同单位的数字，判据刻意保守（两侧都得有该单位的数字才比；容差 6%；**两侧都出现对方没有的值**才报），
全库 1683 对里报出 1 处，就是这一处，没有假阳性。

**2026-09-10 当天又扩到了城市**（地形 6 板块 + 城市 7 段，全库 5906 对、0 处对不上）。
扩的时候**又踩了同一个形状的第三次**：城市字段名是照记忆写的，写了个 `food`，
而 `TravelGuide` 里根本没有这个字段 —— 那一段于是被**静默跳过**，屏幕上照样是「全部通过」。
所以脚本现在还断言：**每个声明的字段名，至少要在一个条目上真的存在**，否则直接判失败。

**这三次是同一件事的三种形态**：忘了 `await`（取到 Promise）、字段名写错（取到 undefined）、
`C6i` 的限定语插在中间（正则取不到值）。**共同点是「取不到值」被当成了「没问题」。**
判据：**任何一个检查，都要能说出自己实际检查了多少个对象**；说不出来的，它报的「通过」不算数。

**这个脚本自己先骗了我一次。** 第一版用 `getTerrainContent()` 取内容 —— 那是个 **async** 函数，
忘了 `await`，于是每个字段都是 `undefined`，**比较了 0 对，却打印「0 处对不上，全部通过」**。
和 `C6i` 那次「限定语插在中间导致规则取不到值、静默退出比较」是同一个形状：
**一个静默取不到值的检查，比一个会报假阳性的检查危险得多，因为屏幕上什么都不会出现。**
所以这个脚本**每次都打印「实际比较了多少对」，并且 `pairs === 0` 直接判失败**。

### 又一个量完之后否掉的防线设想：`C1c`「同国两条断言同一个最高级」（2026-09-10）

既然排他性断言反复被本库自己证伪，很自然想到写个脚本：
**把同一国家里断言了同一个最高级属性的条目挑出来并排看**。

写了原型，指纹取「最/唯一 + 紧跟的那个名词」（`最大|城市`、`only|place`），全库跑出
**368 组**。逐组看下来，**几乎全是假阳性**，而且坏在同一个地方：**指纹抓不到「范围」**。

> 斯普利特「**达尔马提亚**最大城市」、奥西耶克「**斯拉沃尼亚**最大城市」、
> 普拉「**伊斯特拉半岛**最大城市」—— 指纹全是 `最大|城市`，可它们各自的范围互不重叠，
> 三句话同时成立。

真正会出错的恰恰是「范围写错了」那一类（苏梅岛「泰国湾第二大岛」拿安达曼海的普吉来比），
而**范围正是这个指纹抓不到的东西**。要抓它就得做语义比较，那已经不是正则能干的事。

**所以不写这个脚本。** 与 `C6d` 分句版那次是同一个结论，也是同一条判据：
**一个防线要值得存在，它报出来的东西里得有相当比例是真的**；
做不到就别加，否则下一个人会淹在 368 条噪声里，反而更不会去看。

**这一类只能靠人**，判据写在这里：
**写下任何「唯一 / 最……」之前，先在本库同国家的条目里搜一遍那个属性词** —— 全库就在手边，
不需要联网，成本是几秒钟。

- 城市条目的 `howItWorks` 段：**已经是新名**（那是 2026-09 城市深度重构时新写的）；
- 同一个条目的 `identity` 段：**还是旧名**。

也就是说，全州这一条**自己跟自己打架**：`identity` 说「全州是全罗北道道厅所在地」，
往下两段的 `howItWorks` 说「全州是全北特别自治道的道厅所在地」。束草、春川同型。

**为什么改名会漏成这个样子**：改名发生的时候，有人去改了**当时正在写的那一层**
（注册表字段、新写的段落），没有回头扫一遍**早就写完的那一层**。
`identity` 是最早写的一段，也因此是最容易留着旧名的一段 ——
这与上一轮泰国那批「identity 更新了、howItWorks 还是旧的」**方向正好相反**，
再次说明：**「哪一段更容易旧」不是内容的属性，是「上一轮改了哪一段」的属性。**

**处理时定下的一条新规矩 —— 分清「行政单位」和「地区」**：

- 句子说的是**行政单位**（「道厅所在地」「某道的一座市」）→ 写现行官方名，该长就长；
- 句子只是**泛指那一片地方**（「江原道东海岸」「江原道北部的山地」「northern Gangwon」）
  → **把行政后缀去掉**，写「江原」/ `Gangwon`。

第二条不只是图省事：**省改制了，地区名没改**。「江原」这个说法在改制前后都对，
也不会因为下一次改制再过期一次。**能不写行政后缀的地方就别写** ——
这和 `C8` 那条「干脆不写数字只写机制」是同一个思路：**把会过期的那部分从句子里拿掉。**

**防线**：只有全库正则扫描能接住这一类。改名一旦确认，
当场对 `lib/*.ts` 全体跑一遍旧名的正则（中英两侧、注册表与内容文件都要扫），
**不要只改报上来的那一处** —— 这已经是第三次由全库扫描而不是由分批核实发现问题
（AONB → National Landscape、`sokcho`/`incheon` 的红线、这一次）。

### 留痕写在了条目**外面**，于是数留痕的脚本看不见它（2026-09-10）

「哪些地形已经核过」这件事，唯一的机器可读凭据是**条目里有没有 `sources:` 注释** ——
排下一批派谁去核，靠的就是这个计数。这一轮我用一个临时脚本给 41 篇零改动的条目补留痕，
把注释块插在了 `  "<id>": {` 这一行**之前**。

肉眼看毫无区别：注释就贴在条目上方，谁翻到这里都读得到。
但计数器是从 `  "<id>": {` 切到 `  },` 的 —— **条目外面的那几行不在切片里**。
结果是补完 41 篇之后，计数只涨了 11：那 41 篇在脚本眼里**和从没核过一模一样**，
下一轮会被重新派出去核第二遍。

仓库原有的写法是 `    // <field> sources:`（四空格、贴在对应字段前面、在条目**内部**），
`verify:apply-text` 的 `upsertSourceNote` 一直是这么写的 —— 我那个临时脚本只是没照着它写。
把 82 个注释块搬进条目内部之后，计数从 376 跳到 408，意大利与韩国同时补齐成整国收尾。

**这一条和「核过无误也要写留痕」是同一个洞的两半**：那一次是**没写**，这一次是**写了但写在了
脚本读不到的地方**。两次的后果一样 —— 已经花掉的核实工作在下一轮被当成没做过。

**防线**：补留痕不要另写临时脚本，走 `verify:apply-text` 的 `sourceNote` 字段
（它会把注释放对位置、还会覆盖同字段的旧注释）。真要手写，
**写完之后跑一遍那个计数**，看涨的数目对不对得上这一批的篇数 —— 对不上就是位置写错了。

### 「大市」这类制度，会让一个**完全正确的官方数字**变成错的（2026-09-10，土耳其批）

土耳其 2012 年的 6360 号法从 2014 年地方选举起，把 30 个省改成「大市」（büyükşehir），
**大市的市界与省界重合**。于是 TÜİK 公布的「伊兹密尔人口 4,504,185」这个数，字面上
没有一处不对 —— 它就是官方的、最新一期的、口径明确的。

错在**它被摆在哪句话后面**：

> ~~伊兹密尔是土耳其**第三大城市**，人口逾 450 万~~

读者读到「第三大城市」，接着读到「450 万」，得到的结论是「伊兹密尔的城区有 450 万人」。
而这是全省数。**数字对、口径也对、句子还是错的** —— 错在没写出口径，让读者自己补了一个。

同一批里布尔萨更糟一层：原文写「第四大城市，人口逾 216 万」，而 TÜİK 2025 的布尔萨省是
**326 万**。216 万接近布尔萨三个中心区的城区规模 —— 也就是说，**上一个写的人拿了城区数，
摆在了一个会被读成全市数的位置上**，两个方向的错叠在一起，差了一百多万。

**处理**：不是去找一个「城区人口」来替换，而是把口径写进句子里 ——
「按省人口排名」「2025 年省人口逾 450 万（土耳其统计局，省界自 2014 年起与大都会市同界）」。
安塔利亚那条相反：正文原有的「城区约 140 万」核不到 TÜİK 的 `il ve ilçe merkezleri`
一手序列，**那就撤下来、不写**，而不是换一个同样没核到的数。

**这一类为什么没法用 `C6k` 拦**：`C6k` 拦的是「这个国家没有的口径」。土耳其的省、区、
大市**全都是真口径** —— 没有一个词是编的。会出错的是**省略**，不是编造。脚本看不见省略。

### 一个真数字用在了比它大得多的对象上 —— 斯普利特（2026-09-10）

> ~~索林（古萨洛纳）与卡什泰拉是城区连绵的另外两座市镇，**合计约 31 万人**~~

307,289 是**斯普利特连同周边十余个市镇的加总**（2021 年普查），里面首先就包含斯普利特

**那个数字本身是真的、有出处的**，错的是它被挂在了哪个名词上。所以查数字查不出来 ——

### C6d 的「统计时点」取的是整句最大年份，**句里另一个年份会把它遮住**（2026-09-10）

`docs/claims-stale-exempt.json` 报出 `travel/limerick/howItWorks` 这条豁免「已经用不上了」。
按提示的字面意思，那应该是数字更新到最新一期了。**不是**：那一段里的人口还是
2022 年普查数，一个字没动。变的是同一段后来补进了一句
「2024 年 6 月它选出了爱尔兰第一位直选市长」—— `isStale()` 用 `latestYear(s)`
取**整句里最大的年份**当统计时点，于是它看到 2024，判定「不算旧」，静默放过。

**一个和人口毫无关系的年份，把人口的年份遮住了。** 这和上一节「语序」是同一个形状：
规则不是报错了，是**悄悄退出了比较**。

**试过一个修法，量完之后否掉了。** 想法是把判据从「整句」收到「含人口数字的那个分句」
（`；` 切分）。跑全库对比：现行 181 处 → 分句版 194 处，新增暴露 18 处。逐条看这 18 处，
**几乎全是假阳性**，而且都坏在同一个地方 —— 本仓库写「为什么这个旧年份就是最新一期」时，
恰恰是把理由写在相邻的那个分句里的：

| 条目 | 整句 | 分句切开后丢掉的那半句 |
| --- | --- | --- |
| nanchang / jilin-city / leshan / qinhuangdao | 2024 年末常住人口（市统计局；**2025 年公报尚未发布**） | 括号里那句「尚未发布」 |
| paris / strasbourg / marseille / nice 等 7 条 | 2023 年人口……（**法定人口 / reference population**） | 点明 INSEE 法定口径的那一半 |
| athens | 2021 年人口约 64 万；……（**2021年人口普查**） | 点明普查的那一半 |

也就是说：**分句版会去惩罚那些把话写清楚了的句子**，而漏网的仍然是 limerick 那种
「被无关年份遮住」的。收紧判据在这里是负收益，所以不改。

**那这一类靠什么接住**：
① 条目上方的 `// <字段> sources:` 注释 —— limerick 的注释里本来就写着
   「2022 普查之后到 2027-05-09 下次普查之间，爱尔兰城市一级没有官方更新数」，
   这条信息一直是对的、也一直在，只是脚本读不到它；
② `/verify-content` 要求的**六段并排 + 中英并排**通读 —— 这一类只有人（或子代理）
   通读才看得出来；
③ 写的时候的硬性习惯：**一段里出现两个年份时，把人口的年份紧贴人口数字写**，
   不要让制度沿革的年份排在它后面。

豁免表里那条已经删掉（59 条），理由随注释留在条目上方 —— **删豁免不等于问题解决了，
只是承认脚本在这里本来就看不见。**

**规则本身的三处修正**（`scripts/claim-rules.ts`）：「第二大道」是街名不是名次；「常被称为 / often called」和已有的「号称 / 之称」同属限定；
英文口径不止面积与人口（by passengers / vineyard area / number）。

**还没补的漏洞：句子里有年份就被当成有口径。** 瓦尔帕莱索、康塞普西翁、马拉加 / 帕尔马的矛盾，句子里都带着「2017 年」「2023 年」，

但直接去掉年份豁免会让大量「2024 年人口约 X 万，是某国第 N 大城市」重新被报。

**「名次冲突」原型实测（同一天）**：把「某地第 N 大 / 繁忙 某某」与英文 X's second-largest … 按「范围 + 名次 + 名词」分组，

普宜奥山塔顶当山顶、阿连特茹 GIAHS 又被泛化回整片平原、日武瓦维「中世纪荷兰移民」；外加两种新形状 ——
**机场交通写错系统**（慕尼黑「高铁直达」、汉堡「地铁直达」，实际都是 S-Bahn），和**时区**（特内里费「与马德里同一时区」）。

**这一天的结构性结论**：航线解说的错，**大多数不需要联网就能发现** —— 地形 / 城市条目已经核过、航线数据已经核过，
解说只要和它们对不上就是嫌疑。真正要联网的是本库完全没覆盖的东西（途经俄罗斯 / 中亚的地貌、机场交通、航司市场说法）。
所以三个脚本（`check:distance`、`check:zhen` 的汉字数字、`check:routes` 的承运人与支线机型）比 13 个子代理更耐用：
**子代理核的是今天的文本，脚本守的是以后每一次改动。**

### 航线解说第一次联网核实：75 条中国出发航线（2026-09-11，R23a–d，#264）

四批并行：国内 40 条 + 国际 35 条，每条 study / travel × 中英四段。先比对本库已核的地形 / 城市条目，
对不上或本库没有的才联网。**大部分断言直接对上了本库条目**（泰山 1532.7 m、洞庭湖第二大淡水湖、
龙门石窟近 11 万尊、格洛马河挪威最长……）—— 地形 1041 条走完一遍之后，它们成了航线解说的离线参照。

**新形状：解说在描述「这条航线本身」时说错了**（归 `C3-b` / `C1b`，这一类以前只在航班号上见过）：
- `pek-bru`「北京飞布鲁塞尔，2026 年 3 月开航」—— 开航的是国航这一趟；海南航空 **2006 年**起就在飞这对城市。
  **一趟新航班的开航日，被写成了这对城市之间航线的开航日。**
- `pvg-dub`「中国与爱尔兰之间的首条 / 唯一直飞航线」—— 东航自己的新闻稿写的是「继北京之后第二条」。
- `pkx-hel`「中国到北欧最北的一条直飞航路」—— 说不出口径（「航路最北」取决于航迹，不取决于终点纬度）。
判据：**解说里关于航线市场的断言（开航、首条、唯一、最繁忙）和「首座国家公园」是同一种东西**，
而且过期得更快 —— 航司会新开、停飞、复航。写「这趟航班」而不是「这条航线」；「唯一」直接删，不换一个新的「唯一」。

**全程距离可以算，不必查**：
- `can-syd`「全程约九千公里」—— 航司公布 8217 km，按坐标算大圆约 7530 km，原数偏高 10–20%；同批其余航线都在 1–5% 以内。
- `pek-jfk`「高纬度弧线比沿纬线直飞短两千多公里」—— 按两机场坐标算实为约 **3400 km**。这是几何问题。
- `pek-yyz`「约一万一千五百公里」比大圆高约 9%，但跨北极航路实际里程可能更长，**航司公布值没找到 → 开 issue**。
**现在有防线了：`npm run check:distance`**（同一天写的）。`data/routes/*.json` 里有两端机场坐标，
「全程约 X 公里」逐条和大圆距离比，中文的汉字数字自己解析。第一次跑：73 处距离里 **14 条对不上，11 条比大圆还短**
（吉隆坡—浮罗交怡写 370 km、大圆 455 km；古晋—美里写 420、大圆 513；河内—胡志明写 1000、大圆 1160……）——
飞机不可能比大圆飞得更短，所以这 11 条**不需要任何来源就能判错**。另外 3 条偏长太多（萨格勒布—斯普利特 370 vs 246，
像是公路里程）。上面联网核出的 `can-syd` 那条，脚本也会报 —— **本来就不该花一个子代理去查**。
第一版还有一个误报来源：英文「covering about 15,000 km²」是面积，被当成了距离 —— 正则里补了 `km²` 排除。

**`check:zhen` 的盲区：汉字数字**。`pvg-mad` / `pkx-lis` 中文写「平均海拔**六七百米**」，英文与本库地形条目都是 600–800 m ——
中英各挑了一个值，正是 `check:zhen` 立项要抓的形状，但它只比阿拉伯数字，**航线解说的中文大量用汉字数字**
（「三千六百米」「九千公里」），整类都在它视野外。它报「0 处对不上」时，汉字数字那部分实际没比过。
**已补（同一天）**：`check:zhen` 现在也解析汉字数字，「六七百」按区间两端都记。比较对数 6374 → 6514；
首跑只多报两处，**两处都是它自己的假报**（「数十公里」「几十米」被读成 10）—— 补了「前面是 数 / 几 / 上 / 成 / 好 就跳过」之后归零。
也就是说：库里除了已经被子代理抓到的梅塞塔，**汉字数字这一侧目前没有别的中英不一致**。这个结论以前说不出来。

**第二波最大的一类：解说写的承运人 ≠ 航线数据里已核实的承运人**（7 处由子代理报出，然后脚本又找出 10 条）。
- 子代理报出：蒙古 5 条「是航蒙航空运营的国内航班之一」（航蒙航空**没有**国内航班）、`ist-tzx` 飞马航空、`nqz-pwq` 已改名的哈萨克航空。
  这些航线的**数据** 2026-09-07 就核实改正了，解说没跟上 —— 又一次「改了一处、没回头找另一处」，只是这次两处都在航线系统内部。
- **`check:routes` 本来就有一段「解说点名的航司与数据对不上」，一处都没报。** 原因是结构性的：它的探针名单
  取自**当前数据里出现过的航司名**；解说里写错的那几家从来不在数据里，于是「数据改对了、解说没跟上」这个
  它最该报的时刻，它恰好是瞎的。而且它只打印不失败 —— 我这一天跑检查一直是 `| tail -1` 只看最后一行，**报了也看不见**。
- 改法：不猜哪些词是航司名，**只看句式**。「是 X 运营 / 由 X 执飞 / operated by X」里的 X 一定在说承运人，
  逐句拿去比这条航线自己的 `flight.airline`，对不上就**失败**；未核实的航线点名承运人也失败。首跑 199 句里报 27 处：
  11 处是正则误伤（「由国产 C919 执飞」「由经验丰富的机组执飞」「是否仍在执飞」、英文把括号里的机型也抓进来），
  **16 处是真的，分布在 10 条航线**：哈萨克斯坦 5 条中文把 Air Astana 写成「哈萨克斯坦航空」（英文侧是对的）、
  马尼拉 2 条把 PAL Express 写成母公司、萨格勒布—奥西耶克把代码共享方写成承运人、婆罗洲 2 条数据已查明有误却点了承运人。
- **同一个盲区在机型规则里也有**：「解说点名的机型必须与数据一致 / 未核实航线不得点名机型」只认空客、波音、C919，
  **支线机型（ATR、Dash 8、Embraer、Saab）整类看不见**。补上之后又抓出 3 条：萨格勒布—奥西耶克写 Dash 8 Q400（数据 Saab 340B）、
  曼谷—苏梅写 ATR 72（数据 A319）、阿斯塔纳—谢梅伊写 E190（数据 A320，E190 已退役）；另有婆罗洲 2 条「已查明有误却写了 ATR 72-500」。
**判据**：一条检查的探针如果取自「被检查对象的当前状态」，它就会在状态被改正的那一刻失明 —— 探针要取自**句式**或**独立名单**，不能取自数据本身。

**「石炭纪」第三次出现（2026-09-11）**：9 月 10 日把 `oland-alvar` 的「石炭纪石灰岩」改成奥陶纪、又补了 `gotland` 的交叉引用 ——
**注册表 `source` 那一句一直没改**，今天核航线 `arn-vby`（大阿尔瓦荒原被挂到哥得兰岛）时回头搜才带出来。
那天的回头搜为什么没抓到：「石炭纪」在全库出现 46 次，超过回头搜「全库 >10 次就跳过」的噪音上限 ——
和哈萨克斯坦批「2012 / 1972」漏掉注册表是**同一个原因**。改的是常见词（地质年代、年份、常见数字）时，注册表必须手查。
**判据**：只报告不失败的检查段，印在输出中间就等于没有；要么让它失败，要么让人必须看见它。

**老形状，新实例**：
- 条目改对了、解说没跟上：`pek-urc` 乌鲁木齐「离海最远的内陆山城」（城市条目早已写成「之一」）。
- 近名邻居：`pek-hld` 与 `travel/hulunbuir` 中英、`travel-pois` —— 「天下第一曲水」莫日格勒河被写成 **Mordaga**（莫尔道嘎，额尔古纳的另一处林场）。**四处**。
- 同篇自相矛盾：`pek-prg` 开头「波希米亚盆地」、临降落「波希米亚高地」。
- 会过期的量：里海水面「约 28 m」（2025 年约 −29.2 m、仍在降）改为区间 + 「近年仍在下降」。
- 排名说不出口径：「呼伦湖是中国第五大湖」（资料第五 / 第六并存）、海南岛「中国纬度最低的省级陆地」、
  纳土纳「印尼最北端的岛群」（最北是伦多岛）、戈壁英文单侧的「世界第六大沙漠」。

**核实代理的判断，这一波两个方向都偏过**：
- 过报：拉萨「约三千六百米」被报 6 处 wrong（官方 3650 m）—— 这是正确的取整，不改。
- 漏报：海南那句它判 ok，推理是拿海南岛去和另一座大岛比纬度 —— 可「省级」按行政区算，南海诸岛纬度更低，照字面不成立。
- 替换文本又一次越界：纳土纳它建议改成「印尼在南海南部的岛群」—— 那片海域正是红线判据会触发的地方。只删修饰语，不补新定位。
**合并结果时，verdict 与 fix 都只是建议；判定归调用方，理由写进 finding。**

### 克罗地亚 + 菲律宾批：老形状又各来一遍，外加两条关于「核实代理本身」的教训（2026-09-11）

**老形状，新实例**（各自归入已有的类，这里只记一笔）：

- **两个条目争同一个「首座」，而且都不是**（同「本库两个条目争同一个首座」一节，泰国批）：
  `mayon-volcano`「1938 年菲律宾首座国家公园」、`hundred-islands-national-park`「1940 年首座 / 最悠久」——
  阿波山 **1936** 年就设了。百岛那条在同一条目里断言了两次。
- **一个设施生命周期里的另一个年份**（同哈萨克斯坦批 Medeu、捷克电视塔）：
  `gorski-kotar`「1997 年设立里斯尼亚克国家公园」—— 1953 年设立，1997 年只是扩园。
  **同一天第三例**。判据仍是：「设立 / 建成 / 开放」前先问这个对象一共有几个年份。
- **凭空出现的认定**（同「一个凭空出现的专名」一节）：`el-nido-bacuit-archipelago`「2011 年获 UNESCO 世界地质公园」——
  **查无此认定**，菲律宾唯一的 UNESCO 世界地质公园是 2023 年的保和岛。已删，不补。
- **相邻对象属性互换**（同新加坡批 Bukit Batok）：`batanes-islands` 把萨布唐岛（西弧、抬升珊瑚礁石灰岩）
  归到了巴丹岛（东弧、火山）那一组，formation 与 concept 各一次。
- **同一条目两段各给一个数**：`lake-lanao` seeing 写「17 处古老湖泊」、concept 写「15 处」。
  文献本身 15–20 不等，两处都改成不带计数。
- **会过期的状态**（C6-j）：`lake-lanao`「阿古斯水电供棉兰老岛约七成用电」（约 2013–15 年的状态）；
  `krka`「允许游客游泳」（2021 年起园区禁泳）—— 这一条连带 `zrmanja-canyon` 的「克尔卡以游泳区闻名」。
- **排名 + 数字复合**：`sava-river-croatia`「多瑙河最长支流，992 公里」—— 992 无来源；
  国际萨瓦河流域委员会给 945 km（计入萨瓦多林卡源头 990 km），长度排名口径不一，
  唯一无争议的是**水量最大**（ICPDR）。
- **红线**：克罗地亚 7 条跨境候选里只有 `sava-river-croatia` 点了邻国名（「发源于斯洛文尼亚阿尔卑斯山区」），已去掉。
  回头搜报出另外 5 处「Slovenian」，逐条看过都在意大利 / 奥地利条目里，该判据只管克罗地亚条目，放过。

**两条关于核实代理本身的教训**：

1. **结论和证据不一致时，信证据。** 克罗地亚批的代理对 `krka` 判了 `ok`，
   但它自己的 finding 里写着「2021 年后主要开放区改为禁泳」—— 然后用「通用科普语境下仍普遍成立」把它圆了过去。
   只读 verdict 字段会漏掉这一条。**合并结果时要读 finding 正文，不只数 wrong 的个数。**
2. **核实代理给的替换文本，也要过同一套判据。** 菲律宾批的代理建议：
   拉瑙湖水电「2024 年约三成」（只有 3 级来源，且与 NPC 官方「逾 50%」冲突）、
   艾尔尼多补上「1991 年设立、1998 年扩展」的保护区年份（**没给来源**）、
   古老湖泊改成「不到 20 处」（而它引的维基恰好写的是 20 处）。
   三处都是**用一个新的、看起来合理的数去替换旧的错数** —— 正是这本台账最常记的那种错。
   实际处理：水电只写定性下降、艾尔尼多只删不补、古老湖泊不带计数。
   **「修」和「写」是同一件事，修的时候一样不能补一个看起来合理的答案。**

### 哈萨克斯坦批：一个英里换算被当成了另一个维度，一个改造年被当成了建成年（2026-09-11）

- `karagiye-depression`「长约 40 公里、**宽约 25 公里**」—— 实际宽约 **10 km**。
  「25」大概率来自英文资料里的「40 kilometres (**25 mi**) long」：**长度的英里换算，被当成了宽度的公里数。**
  这是「真数字挂到错对象」的又一种变体：挂错的不是地点、不是证据类型，是**维度与单位**。
  判据：一个数字在来源里紧跟在括号里、带着另一个单位出现时，它多半是前一个数的换算，不是新信息。
- `medeu-gorge`（seeing + history 两处）「1972 年建成的高山溜冰场」—— 实际 **1951 年建成开幕**，
  **1972 年只是改建为人工制冷冰面**。与捷克电视塔「动工年当建成年」、蒙古恐龙蛋「考察启动年当发现年」同族：
  **一个设施的生命周期里有好几个年份，正文取了其中一个，却给它贴了「建成」的标签。**
- `burabay-hills`「区内湖泊逾 30 座」—— 查得到的只有「**14 座主要湖泊**」，另有未计数的小湖；
  「逾 30」找不到任何来源，改为有来源的口径。
- `altyn-emel-singing-dune`「图兰寒冬荒漠 2016 年列入」—— 实际 **2023-09-20** 列入（三国联合申报）。
  2016 从哪来的没有查明，不猜。

**回头搜这次漏了注册表**：打完补丁回头搜报「全库别处没有残留」，但注册表 `source` 里
这四个旧值其实都还在（2012 / 25 公里 / 1972 / 逾 30 座）。原因是回头搜为了压噪音，
**全库出现超过 10 次的片段就跳过** —— 而「2012」「1972」这种年份在全库到处都是，
恰好是被跳过的那一档。**「没有残留」只对它实际搜了的片段成立**；改的是年份或常见数字时，
注册表仍要手动查一遍（这次已手动同步）。

### 「真数字挂到错对象」又长出三种新变体（2026-09-11，印尼 / 马来西亚 / 蒙古批）

本库最高发的这一类，这三批里各出现了一种以前没见过的形状 —— 挪走的不再是地点或数字，而是**对象的种类**：

| 条目 | 挪的是 | 详情 |
|---|---|---|
| `niah-caves`（马来西亚） | **证据的种类** | 「部分头骨碎片测定距今约 6.5 万年」—— 著名的「深洞头骨」2016 年重测是约 3.7–4.5 万年；「6.5 万年」确有出处，但对应的是附近 Gua Dagang 的**石器**。数字对、年代对，挂到了另一种考古证据上 |
| `gobi-altai`（蒙古） | **一个已经不存在的东西** | 「伊赫博格德峰山顶保留有小型冰川」—— The Cryosphere 2023 原文 *Ikh Bogd Massif is unglaciated today*，末次冰期古冰川约 2–1.7 万年前就已消退，现在只有季节性积雪。**古冰川被当成了现代冰川** |
| `mount-kinabalu` / `crocker-range`（马来西亚） | **两个相邻地物之间的从属关系** | 京那巴鲁写自己「为克罗克山脉的一部分」，克罗克写自己「是京那巴鲁花岗岩体的组成部分」—— 实际克罗克是深海浊积沉积岩，京那巴鲁是**侵入**其中的独立年轻花岗岩体。两条互相把对方写成了自己的一部分；而 `mount-kinabalu` 自己的 `distinguish` 段本来写对了 |

第二条值得单独记：**「会过期的量」里最极端的一种不是数字变了，是这个东西已经没了。**
与吕根的眼镜蛇头海蚀柱（2024 年倒塌）、德国南施内费尔纳冰川（2022 年被除名）是同一族 ——
**写任何冰川、海蚀柱、火口湖颜色这类会消失或会变的地物，都要问一句「现在还在吗」。**

### 把「回头 grep」从判据变成机械动作（2026-09-11，`verify:apply-text` 加了一步）

昨天记下的判据是：**修完一条事实，拿那个「错的值」在全库 grep 一遍再收工。**
它的问题是——**靠自觉**。一天之内我栽了三次，三次都是子代理在**后面那一批**里替我抓出来的：

- `oland-alvar` 的「石炭纪」改了，`gotland` 的交叉引用原样留着；
- `bardenas-reales` 的「阿拉贡王室」改了，`ebro-basin` 里还写着阿拉贡；
- `torne-river` 里捏造的「梅尔梅奥河谷」改了，而它**一共住在四个地方**。

也就是说，这条判据当时的执行率是 0/3，全靠运气补上。**所以让脚本来做。**

`verify:apply-text` 打完补丁后，现在会自动把「这次改掉的那几个字」拿去搜
五个内容文件 + 注册表，列出还留着的地方。**只报告，不拦截** —— 命中不等于有错
（「安特卫普港」在别处出现 8 次都是正常的地理指代），判断仍然归人。

**难点全在「怎么知道改掉的是哪几个字」**，试错了三版：

1. **按标点切段，比对整段** —— 没用。补丁往往在一个句子中间改几个字，
   整句作为一段拿去搜，只会命中它自己。
2. **掐公共前缀 + 公共后缀** —— 大部分能用，但两处失败：
   `石炭纪` → `密西西比亚纪` 两侧都以「纪」结尾，后缀把「纪」吃掉、只剩「石炭」；
   而补丁经常在句尾**追加**从句（本轮很多），公共后缀直接是 0，整句又被当成改动部分。
3. **n-gram 覆盖**（现用）：find 里每个位置，只要它所在的某个 4 字窗口在 replace 里出现过，
   就算「没动」；剩下连成片的位置就是真正改掉的字。
   `……的石炭纪石灰岩……` → 「石炭」（「纪石灰」在 replace 里，覆盖到了）；
   `the Kingdom of Aragon's royal house` → 「Aragon」。

门槛：中文 ≥2 字、拉丁 ≥5 字符 ——「最大」→「第二大」删掉的只是一个「最」字，搜它没有意义；
>40 字也跳过，那是整句重写。

**用今天的三个真案例回放验证**：改 `ebro-basin` 的「纳瓦拉王室」，脚本报出
「纳瓦拉」仍在 `terrain-content.zh/en`、`travel-content.zh`、`terrain-registry` 共四处 ——
正是当初漏掉的那种跨条目引用。

### 「故事越顺越要查」这条判据，写进 SKILL 的第二天就中了（2026-09-11，丹麦批）

### 航线解说 × 地形条目的最高级交叉核对：终于做了，一次捞出 5 处（2026-09-11，新脚本 `check:rvt`）

`CLAUDE.md` 规则 ⑥-a 里写着「**不花钱的第一步**：把航线解说里的最高级／排名，
拿去和本库已核过的地形条目对，不需要联网」—— 写下之后一直没做。这一轮做了。

| 航线 | 航线解说说的 | 地形条目（已核实）说的 |
|---|---|---|
| `dub-cfn` | 格伦维是「爱尔兰面积**最大**的国家公园」 | **第二大**（威克洛约 23,000 ha 更大，nationalparks.ie 1 级） |

| `cdg-nce` | 凡尔登是「欧洲**最大**的峡谷之一」 | 已改成「常称欧洲**最深**的峡谷之一 —— 这个说法没有统一的国际排名口径」 |
| `cph-rnn` | 博恩霍尔姆是「丹麦全境**唯一**大面积可见花岗岩基岩的地区」 | 「……的地区**之一**」——**而且英文侧本来就有 one of the only，只有中文丢了限定** |
| `rkv-hfn` / `rkv-ifj` | 瓦特纳「欧洲最大的冰川，占冰岛约**八分之一**」 | 2026-09-09 已把「7700 / 8%」改成 7500–7600 km²、**约 7%**；且「欧洲最大」要带**按体积算**的口径 |

最后一条尤其值得看：**「八分之一」（12.5%）比地形条目当初改掉的 8% 还离谱，而且它接近的是
「国家公园占冰岛约 14%」那个数** —— 冰原和国家公园是两个对象，数被串了。

**为什么这一类逃得掉所有防线**：`check:claims` 只看一句话自己写得规不规范
（有没有限定语、有没有年份），不比对两处内容说的是不是同一件事；
`check:zhen` 比的是中英两侧的数字，比不了航线与地形之间。**这是第三套内容系统欠的账。**

**新脚本 `npm run check:rvt`**（`scripts/check-route-vs-terrain.ts`）：
把两边点到同一个地形／锚点、又都带最高级的句子摆在一起。
280 条航线 / 282 个含最高级的句子，配出 168 组，其中 17 组被启发式标 ⚑。

**它不是棘轮，也不是门禁 —— 永远 exit 0。** 判对错必须人看：同一件事换个说法就不同字，
绝大多数配对是一致的。留着它是因为**零成本**（不联网）且第一次跑就 5/168。

**做这个脚本时自己踩了两个坑，都记下来**：

1. **第一版配出 0 组** —— 我按 `t.name` 取地形名，而注册表上这个字段叫 `nameZh`
   （`name` 只存在于 `landmark` 里）。**文件末尾那句「三个数都要非零」的断言当场拦住了它** ——
   这是「取不到值被当成没问题」第四次，也是第一次**在写出来的当下**就被自己的断言接住。
   顺带发现该用的是**两个**字段：航线解说点名的往往是锚点地物（「贡嘎山」「布罗肯峰」），
   不是地形名（「横断山脉」）。
2. **⚑ 标了 50 组，其中绝大多数是噪音** —— 因为我把「约 / 左右 / 大致」也算成了限定语，
   于是「面积**约** 1.7 万平方公里」这种句子全被当成软断言。
   **那是数值的约数，不是排名的限定，两者不是一回事。** 收紧到只认「之一 / 常被称 / 据称」
   之后 50 → 17，剩下的基本都值得读。

### 一个**该国地质调查局明确否定的分类**，被当成既成事实写了三段（2026-09-10，德国批）

### C6-d 数字有年份，但**不是最新一期** ⚠️ 2026-09-07 用户直接指出

| | |
|---|---|
| **症状** | 数字带了年份、也有官方来源，但那是上一期甚至更早的发布，最新一期早就出来了 |
| **防线** | **脚本**（`check:claims` 的 `C6d`：易过期量的统计时点必须 ≥ 当前年 − 1，普查除外） |
| **还会再犯吗** | **每年都会**，因为它是纯时间衰减；但现在会被脚本当年报出来 |

原话：**「今年已经是 2026 年了，为什么现在这些数据还用的是 2024 年的人口数据？」**

这条是在刚补完 C6（给数字配年份）之后立刻被指出来的，说明**补年份只解决了一半问题**：
读者知道了这是哪一年的数，但不知道**这是不是最新的**。而各国统计机构的节奏很规整 ——
N 年的年度数据基本在 N+1 年上半年发布。所以在 2026 年 9 月，正确答案应当是 2025 年的数；
我们写的是 2024 年的，**整整落后一期**。

根因不在数据源，在**核实时的停止条件**：子代理搜到一个带年份、带官方出处的数字就收工了，
没有再问一句"这是不是最新一期"。所以这一条现在写进了 `content-verifier` 的红线和
`/verify-content` 的 prompt 模板：**必须报告「更新一期发布了没有」，没发布的要写明该机构
的常规发布月份**，好让下次知道什么时候回来刷新。

**脚本怎么判**：句子里同时出现易过期量（人口）和年份时，取句中最大的年份当统计时点，
早于 `当前年 − 1` 就报。**普查例外**（句子里有「普查 / census / 国势调查」）—— 人口普查
五年或十年一次，菲律宾 2024 年普查确实就是最新一期。

顺带说明一个**看似误报、其实是真问题**的情形：像「1923 年成为首都……人口约 X 万」这种句子，
句中唯一的年份是历史年份，脚本会按 1923 判为"不是最新一期"。它归类归错了（本质是 C6
缺年份），但**该报还是该报** —— 那个人口数字确实没有时点。

首次扫描的存量：**585 处**（2024 年 197、2023 年 50、2022 年 36、2021 年 98、2020 年及更早
131 等），集中在 `howItWorks` 370 处、`identity` 215 处。已按棘轮锁定，只许降不许升。
第一轮刷新（2026-09-07，中国 27 城 + 港澳 + 中国/德国概览）降到 **526**。

**刷新一轮下来验证了用户的判断**：查的 29 座中国城市里，**28 座的 2025 年公报都已发布**
（集中在 2026 年 3—6 月），没有一座是"2024 仍是最新"。也就是说这批数据确实整整落后了一期。

**刷新时的三个坑**：

1. **不要默认"又涨了"**。这一轮里北京（2183.2 → 2180.0 万）、重庆（3190.47 → 3187.26 万）、
   桂林（493.84 → 490.86 万）、西宁（247.69 → 247.56 万）、全国（140828 → 140489 万）、
   德国（8360 → 8350 万）、香港（753.18 → 751.83 万）都是**下降**。
2. **"新一期没发布"和"新一期发布了但我拿不到数字"是两回事**。哈尔滨的 2025 年公报
   2026-06-03 已发布，只是正文 PDF 托管在内网 IP、公网访问不到 —— 这种情况不能标成
   "2024 仍是最新"，要如实记 unknown 并开 issue。
3. **分项口径可能不跟着主口径更新**。重庆 2025 年公报没有再单列"主城都市区 21 区县"，
   所以正文里这一项如实标注仍是 2024 年末的数，而不是拿全市数字去覆盖它。

**刷新会连带查出排名断言的失效**（2026-09-07 澳大利亚那批）：拿最新一期数据重排一遍，
两处排名当场垮掉 ——

- 芒特甘比尔「南澳人口第二多的城市」：按 ABS 城区口径，维克托港—古尔瓦 30,900 已**反超**
  芒特甘比尔 30,875，只差 25 人（前者两年增 3.5%、后者仅 0.5%）。改成不排名次的表述。
- 班伯里「西澳第三大人口中心」：实际是**第一** —— 珀斯以外西澳的排序是班伯里 84,332 >
  巴瑟尔顿 46,023 > 杰拉尔顿 42,104 > 奥尔巴尼 38,287。这条原本就写错了，
  刷新数据时顺带撞见。

**刷新还会撞见同一条目内部自相矛盾**（2026-09-08 加拿大批）：白马 `identity` 段写
「育空四分之三的人口住在这里」，`howItWorks` 段写「占全地区的七成」—— 同一件事两个数。
用最新数算是 34,129 / 48,278 ≈ 70.7%，即便按 2021 年普查数（28,201 / 40,232 ≈ 70.1%）
也是七成，`identity` 那句从一开始就是错的。**两段分别成文的后果就是这样**，
所以刷新时要把同一条目的所有段落一起看，不能只改被脚本报出来的那一句。
同批的武汉、澳门也是这个毛病（identity 已刷新、howItWorks 还停在旧年份）。

**「不逐年更新」也是一种合法答案**：ABS 只在普查年更新 UCL（城区中心）口径，所以
巴瑟尔顿「2021 年城区 2.7 万」不是过期，要等 2026 年普查结果。这种要在正文里写明
「此后未逐年更新」，而不是硬换成一个范围不同的口径。米尔迪拉那条正是反例的原型：
镇区 UCL 3.6 万与显著城区 SUA 5.4 万范围差很多，直接替换会让读者以为镇区一年暴涨 50%
—— 两个口径并列写明才对。

**发布月份汇总在 [`data-refresh-calendar.md`](data-refresh-calendar.md)**，那张表回答的是
「一个数字什么时候会过期、到时候去哪里取新的」。本轮实测到的：中国国家统计局 1 月中旬快报 / 2 月底公报；
各市公报次年 3—6 月（北京、天津、重庆 3 月，南京、青岛、杭州、郑州、武汉、乌鲁木齐、
银川、西宁 4 月，广州、深圳、西安、昆明、石家庄、太原、沈阳、贵阳 5 月，桂林、合肥、
哈尔滨 6 月）；德国 Destatis 1 月初值、6 月正式值；香港统计处年中人口 8 月出临时数、
次年 2 月出修订数，年终人口 2 月；澳门 DSEC 按季，季末后 6—8 周。

### C6-g 已核实的数字被**同一机构的方法论修订**整体推翻（2026-09-08 发现）

| | |
|---|---|
| **症状** | 数字有年份、有官方来源、上一轮刚核实过 —— 然后官方自己改了方法，把那一年的官方值也改了 |
| **防线** | **无脚本能拦**（脚本看不出「这个数字已被官方修订」）；只能靠刷新时留意机构有没有发方法论说明 |
| **还会再犯吗** | **会**，但频率低；每次影响一整批 |

**实例**：葡萄牙 INE 2026-06-22 发布《Estimativas de População Residente – 2025》时，
首次完全基于行政数据源估计，并整合了 AIMA（移民与庇护管理局）的登记数据 ——
**同一套新方法回溯修订了 2021–2024 整个序列**，因为此前系统性低估了外籍居民。

法鲁那条是现成的例子：正文里写的是「2024 年人口约 7 万」，**标了年份、标了来源、
上一轮核实过**，而 INE 把 2024 年的官方值从 70,347 上修到了 **80,316（+14%）**。
里斯本同期从 575,739 修到 665,141（+16%）。

**教训**：「已核实 + 有年份 + 有官方来源」不等于永远正确。刷新时除了问「有没有新一期」，
还要留意**这一期有没有连带修订旧年份** —— 机构发这种修订时通常会在新闻稿里写明方法变更，
`sources` 注释里应当记下来，让下一轮知道这批数字的基准换过。

### 棘轮本身的一个反向激励：分开卡 C6 与 C6d，会惩罚正确的做法（2026-09-08 修）

给一个没年份的数字**补上年份**，是 CLAUDE.md 明确要求的做法。但如果补上的年份比去年还早，
这一句就会从 `C6`（缺年份）挪到 `C6d`（不是最新一期）—— 两条分开卡的话，
**做对事反而让棘轮变红**，而最省事的做法变成「干脆不写年份」。

2026-09-08 印尼那批撞上了：`C6 −14`、`C6d +10`，总量其实降了 4，棘轮却报失败。

**修法**：两条合成「C6 族」一个预算来卡。这样
- 「把无年份改成有年份」不会失败（总量没变，只是从一格挪到另一格）；
- 「凭空多写一句没年份的人口」照样失败（总量涨了）—— 后者才是这条棘轮要拦的东西。

**一般化的教训**：**棘轮的分格方式本身会塑造行为。** 如果两类之间存在「修 A 就会变成 B」的
合法迁移路径，那它们必须合成一个预算卡，否则这条自检就会把人往错的方向推。

### C6-d 的反面：**年份旧不等于过期**，得有地方记下来（2026-09-08 建机制）

`C6d` 报出来的条目里，有一批**永远不会「清掉」**，因为该地就是没有更新的数：

| 成因 | 实例 |
|---|---|
| 该级别公报本来就不含人口 | 喀什市、和田市、巴楚县、伊宁市、香格里拉市、阿里地区 |
| 那一年起只发户籍人口 | 齐齐哈尔、宜宾、大连、泉州 |
| 那一版公报把人口章节删了 | 南通（2025）、临沂（2025）、阿勒泰（2024） |
| 公报取不到数 | 遵义/汉中/克拉玛依（纯图片）、北海/曲阜（证书失效、反爬）、泸州（PDF 无文字层）、牡丹江（官网 420 拒访）、镇江（列表页抓不全） |

**不建机制会怎样**：每一轮核实都把它们重新报出来 → 下一个人再去核一遍、得出同样结论 →
或者更糟，**为了让计数下降而硬填一个没核到的数字**。第三种是真正危险的那个。

**做法**：`docs/claims-stale-exempt.json` 逐条记 `key / reason / confirmedOn / recheckAfter`，
`check:claims` 把它们从 C6d 计数里摘出来单列。这张表有两条自我维护的提示：

- `recheckAfter` 到期 → 打印「该回去看看有没有新一期了」。**这把「什么时候该回来」
  从人的记忆搬进了脚本** —— 各机构的发布月份本来就记在 `docs/data-refresh-calendar.md` 里，
  到期日就是照它填的。
- 表里某条**已经不再触发 C6d** → 打印「这条用不上了，确认后删掉」。
  建表当天就靠这条清掉了 4 条（那几个 `howItWorks` 已经在同一轮改成了「普查人口」写法）。

**加豁免的前提**：条目上方必须已经有 `// <field> sources:` 注释写清为什么。
**不写理由的豁免等于把问题藏起来**，比不豁免更坏。

### C6-h 注释里写对了，正文没同步（2026-09-08 发现）

| | |
|---|---|
| **症状** | 条目上方的 `// <字段> sources:` 注释标的口径是对的，正文里却写成了另一个口径 |
| **防线** | **无脚本能拦**（脚本读不懂注释与正文的语义对应）；只能核查时**先抄原文再对注释** |
| **还会再犯吗** | **会**，尤其在「查到的是户籍、正文要写常住」这种口径转换的时候 |

**实例**：儋州 `identity` 写「常住人口约 108 万（2022 年）」，而同一条目上方的注释写的是
**「2022 户籍 108 万」**。查到的时候分得很清楚，落笔时把「户籍」两个字丢了 ——
户籍 108 万与常住 102.87 万（2025 年末）差着 5 万人，还是两个完全不同的统计概念。

**为什么值得单列一类**：这不是"没查"，也不是"查错"，是**已经查对了的信息在写入时降级**。
它的隐蔽之处在于，事后审计如果只看注释，会认为这条是干净的。
所以核查流程的第一步固定为**先把正文原句抄出来，再和注释逐字对照**，
不要直接从注释推断正文写了什么。

**第三个方向：中文把英文里有限定的说法收紧成了绝对断言。**
凯恩戈姆条目的英文写的是「the **largest surviving** stand of native forest in Scotland」，
中文写成了「苏格兰**仅存**的大片原生林」。阿伯内西森林确是苏格兰现存面积最大的原生松林，
但远不是仅存的一片（罗西缪库斯、格伦阿弗里克、拉诺赫黑林都还在）。
「最大」和「唯一」之间的那一步，是在改写中丢掉限定词时迈过去的。

到这里，**中英分歧已经出现过三种方向**，值得放在一起记：

| 方向 | 实例 |
|---|---|
| 英文凭空多出一个数字 | 吉林市 / 乐山 / 宜昌的英文在「公报未单列市区人口」之后又给出市区人口 |
| 注释与正文不同步 | 儋州（注释标「户籍」、正文写「常住」）、阿雅克肖（注释还在描述已修好的问题） |
| **中文把有限定的说法收紧成绝对断言** | 凯恩戈姆「largest surviving」→「仅存」 |

三种都不是「查错了」，而是**同一件事实在两处表述之间漂移**。
所以核查流程的第一步固定为**把中英两版和注释三栏并排抄出来**，而不是只读一处。

**反方向也会发生：正文改对了，注释还停在旧问题上。**
阿雅克肖的注释一直写着「identity 的『约7万』偏低」，而正文早已改成 7.6 万（与 INSEE
2023 年市镇法定人口 76,320 一致）。这种滞后注释比没有注释更坏 —— 下一个来核查的人
读到「这里有个已知问题」，会去修一个并不存在的错。**修正文的同时必须回头改注释**，
注释描述的是当前状态，不是修改史。

**同一个国家内不同批次的核源深度会有落差。**
法国批 1（里尔/里昂/波尔多/南特/阿雅克肖）按标准写清了口径并留有 `// identity sources:` 注释，
批 2（安纳西/阿维尼翁/蒙彼利埃/兰斯/科尔马）只写了年份、没写「市镇法定人口」这个口径 ——
数字全对，缺的是口径。**补一个国家的新城市时，要照着这个国家已有条目的写法对齐**，
不能只对齐"有没有年份"。

### C6-e 价格没有年份

| | |
|---|---|
| **症状** | 票价、门票、通票、打车费写了一个具体金额，没说是哪一年的 |
| **防线** | **脚本**（`check:claims` 的 `C6e`：句中同时出现金额与花钱相关的词、又没有年份就报） |
| **还会再犯吗** | 存量已清零，新写的会被当场拦下 |

**原型**：维也纳「五条地铁线、有轨电车与公交用一张 **365 欧元**的年票贯通」。
这个价格自 2012 年起十四年没动过 —— 正因为它十几年不变，谁也不觉得它会过期 ——
而它恰恰在 **2026 年 1 月涨到了 467 欧元**，维也纳交通公司同时宣布今后逐年调价。

另一例是和田「机场出租车约 20 元可达」：没有年份、没有来源，出租车运价又由地方价格
主管部门定期调整。按红线**不补一个查不到出处的金额**，改写成车程（「打车十来分钟可达」）。

**写法**：要么写「年份 + 金额 + 出处」，要么不写金额、改写成不会过期的表述（车程、
相对贵贱）。**读者会拿价格当预算依据**，一个没有年份的价格比没有价格更糟。

脚本判据是「句中有金额 **且** 有花钱相关的词」：只看金额会把 GDP、造价、投资额一起报
出来；只看词又会漏掉「一张 365 欧元的年票」这种数字在前、名词在后的语序。

### C6-f 签证天数写死

| | |
|---|---|
| **症状** | 正文直接写「30 天免签」这类具体天数，而签证政策是变动最频繁的一类信息 |
| **防线** | **脚本**（`check:claims` 的 `C6f`；带「以官方最新公布为准」这类免责语的放过） |
| **还会再犯吗** | 存量已清零，新写的会被当场拦下 |

项目本来就有这条口径（`CLAUDE.md`「中国政策类内容口径」：签证/免签天数不写死，
只说"近年放宽、以国家移民管理局最新公布为准"），但它只是一句嘱咐，管不住其他国家的条目 ——
富国岛那条「2012 年启用的国际机场与 **30 天免签**」就漏过去了。现在把它变成脚本，
适用于所有国家。

**正确写法的范例**（脚本会放过）：哈萨克斯坦概览「多国公民可享受最长 30 天免签入境，
**具体以哈萨克斯坦外交部最新公布为准**」—— 带了转向官方口径的免责语，读者知道该去哪里查。

## D 类 · 功能实现与内容脱节

### D1 解说与数据自相矛盾

| | |
|---|---|
| **症状** | 解说文字点名的机型和数据字段里的机型不是一个 |
| **防线** | **脚本**（`check:routes` 交叉校验机型 + 报告航司名不一致，且未核实航线不得点名机型） |
| **还会再犯吗** | 机型**不会**（硬断言挡住）；航司名会，但**当轮就会被报告抓到** |

实例：北京—华沙解说写"波音 777"而数据是 A330；北京—乌兰巴托解说写 C919 而数据是
737 MAX 8（C919 实际飞的是 CA723，不是 CA901）。
另有一处**假阳性**值得记住：蒙特利尔—温哥华解说里的"747"指的是机场快线巴士线路号，
不是机型 —— 脚本已把它排除，说明这类交叉校验必须留例外口子。

**2026-09-07 扩到航司名**：核实批次改了数据里的 `airline`，解说里的航司名不会跟着改 ——
土耳其 ist-nav / ist-dnz 数据改成土耳其航空、解说还写 AJet，越南 dad-sgn 数据改成越捷、
解说还写"是竹子航空运营的国内航班之一"。于是给 `check:routes` 加了一条**航司名扫描**
（报告，不是断言）：解说里出现某家航司的名字、数据里却是另一家，就打印出来。
它上线当天就自己抓到了第五处：哥本哈根—博恩霍尔姆数据在丹麦批已改成丹麦航空运输
（Bornholmerflyet）的 PSO 航线，解说还写着"北欧航空"。
做成报告而不是断言，是因为航司名会与普通词撞车（Norwegian / Iberia / Vueling），
硬拦会误伤；`CARRIER_WORD_COLLISIONS` 与 `BENIGN` 两张表记的就是这些口子。

### C6i 同一条目的两段给出互相矛盾的人口（2026-09-08 立类并加脚本）

| | |
|---|---|
| **症状** | `identity` 写一个人口、`howItWorks` 写另一个，差得离谱，读者不知道信哪个 |
| **防线** | **脚本**（`check:claims` 的 `C6i`，棘轮基线 0） |
| **还会再犯吗** | **不会**（被脚本挡住） |

**为什么逐条人工核实抓不住它**：核的时候注意力在「这个数对不对」上，
不在「同一篇里另一段写的是什么」上。这一轮人工核实撞见了首尔、库尔勒、济州市、
塞萨洛尼基四个，剩下 11 个是脚本扫出来的。

已抓到的形状有四种：

| 形状 | 实例 |
|---|---|
| 两段都过期，还互相打架 | 首尔 950 万 / 960 万（最新是 928 万） |
| 一段查无出处 | 库尔勒「五十余万」/「2020 年约 78 万」（七普实为 779,352） |
| 两段各用一个口径，都没写明 | 济州市「含外国籍 50.3 万」/「内国人 48.4 万」；统营同理 |
| 改了一段没改另一段 | 塞萨洛尼基 identity 已改成「地区单位」、howItWorks 还写着「都会区」 |

**还有一种最凶的：行政区划合并。** 越南 2025 年把 63 个省市并成 34 个 ——
胡志明市并入平阳省、巴地—头顿省后从约 900 万变成约 **1400 万**，
芹苴并入后江省、朔庄省后从约 120 万变成约 **420 万**。
两条的 `howItWorks` 都已经写了并区后的数，`identity` 停在并区前，
一条目里两个数差出一倍还多。**合并会让人口一夜之间翻倍，比年度增减凶得多**；
凡是这类国家（越南 2025、中国的撤地设市…）都要按合并后的边界重核，
而且要把合并这件事写进正文，不能只换数字。

**脚本的判据**（`scripts/check-claims.ts`）：两段各取一个「全市档」的人口数
（句中带 `市区/城区/都会区/新区/urban/metropolitan/district…` 这类次级口径词的不算），
相差超过 5% 就报；一段是普查数、另一段是年度估计时放过 —— 那本来就会差一截。
中文的数字要求紧跟在「人口」后面，英文取句中第一个带单位的数：
不这样限定的话，「市域约 1.5 万平方公里」会被当成人口、「2,189 万」会被断成「189 万」。

### D1b 免责声明与数字自相矛盾：说了「公报未单列市区人口」又给出市区人口（2026-09-08 发现，[#212](https://github.com/AudreyYZY/skyterrain/issues/212)）

| | |
|---|---|
| **症状** | 一句话里先写「（公报未单列市区人口）」，紧接着又给出「市区约 X 万」 |
| **防线** | **脚本**（`check:claims` 的 `D1b`，中英各一套正则，棘轮基线 0） |
| **还会再犯吗** | **不会**（被脚本挡住，基线是 0，新写一处就失败） |

三个实例，**全在英文版**，中文那边老老实实写着「（公报未单列市区人口）」：

| 条目 | 英文多出来的数字 | 该市真实的城镇人口 |
|---|---|---|
| 吉林市 | about 1.82 million in the urban area | 233.39 万（2024，吉林省统计局） |
| 乐山 | about 1.23 million in the urban area | 177.1 万（2024） |
| 宜昌 | about 1.6 million in the urban area | 公报未单列 |

乐山那个 123 万**恰好是镇江条目里的市区人口** —— 所以这不是"估了一个数"，
更像是双语铺开时从相邻条目串了一句过来，而串过来的位置正好紧跟在自己的免责声明后面。

**为什么值得单列一类**：它和 C6 那一整族都不同 —— 数字既不是过期，也不是查错，
而是**这句话自己跟自己打架**。一个从来没查过的读者也能看出矛盾，但逐条人工核实
反而容易滑过去（注意力在"这个数对不对"上，不在"这句话该不该有这个数"上）。
本轮 12 城人工核实撞见了两个，第三个（宜昌，不在这批 12 城里）是靠中英对照扫描扫出来的。

**顺带的一条**：北海的「市区约 78 万」是**中英都有、但来源注释里根本没提**的数字。
北海确实有过「市辖区常住人口」口径，但可查序列止于 2018 年的 73.85 万，此后各年空白 ——
78 万应是按历史增速外推后被当成了实数。这类"外推值冒充实测值"没有脚本能拦，
只能靠**核实时先看注释里有没有这个数**：注释没有的数字，正文就不该有。

### D2 解说说到哪、镜头却不在那

| | |
|---|---|
| **症状** | 播报讲到某个地方时，镜头还在几千公里之外；北京—纽约"看不到到达纽约" |
| **防线** | **脚本**（`check:anchors` 报每篇镜头滞后；`check:flight` 报干飞时长） |
| **还会再犯吗** | **改解说文字就会**，所以改完必须重跑 `npm run gen:anchors` |

**根因**（三层）：① 镜头进度只由时间推进，与解说没有任何绑定；② 解说篇幅没有按各段
航程配额分配，一段占全程 35% 却只分到 15% 的字数，镜头必然落后；③ 匹配规则漏了大量
情况（括注、并列名、通名后缀、英文按裸 `includes` 匹配导致 `Easter` 命中 `eastern`…）。

**修法**：逐句锚点表（`lib/route-anchors.data.ts`）+ 按段配额重写 24 条洲际解说。
镜头滞后从中位 319 km / 最大 8344 km 降到中位 6 km / p90 382 km。

### D6 自检的断言把分母写错了对象（2026-09-08 浏览器实测发现，[#207](https://github.com/AudreyYZY/skyterrain/issues/207)）

| | |
|---|---|
| **症状** | `check:flight` 280 条全绿，可洲际航线落地前几秒画面明显糊掉、扫得飞快 |
| **防线** | **脚本已修**（`check:flight` 改用与渲染同一条取景高度剖面；阈值从 `route-flight.ts` 取，两边不再各写一个 0.6） |
| **还会再犯吗** | **同类会**——只要断言里的某个量与线上实际用的量是两份独立的实现 |

**根因**：断言是「每秒扫过的距离 / 取景高度 ≤ 0.6」，写的时候分母取了
`plan.cruiseHeightM`。但线上真正用的分母是 `cameraHeightAt(p, …)` —— 起飞后
7% 与落地前 13% 的进度里，它会从巡航高度压到 26 km（为了让人认出是哪座城市）。
下降是按进度比例排的，地速是按航段排的，两者互不知情：镜头一边掉高度一边还在
每秒推进几十公里，实测 pek-jfk 落地前 5 秒达到 **1.41 个取景高度/秒**，全库
**52 条航线**在起降段超红线、峰值 **3.25**。自检一条都没报，因为拿巡航高度当
分母时这些帧算出来只有 0.16。

**这类错误的形状**：不是阈值定错了，也不是漏了某条航线 —— 是**断言量的那个东西，
和线上真正发生的那个东西，不是同一个量**。全绿因此毫无意义，而且比没有自检更糟：
它给了一个"这块已经守住了"的错觉。

**怎么发现的**：在浏览器里用受控时钟逐帧驱动了一遍真实航线（把 `requestAnimationFrame`
与 `performance.now` 换成手动推进的虚拟时钟，逐帧读 `viewer.camera` 的实际经纬度与
高度），量的是**渲染循环真正摆出来的相机位姿**，而不是模型的预测值。
离线自检只能验模型自洽，验不了「模型的输出有没有被线上按同样的口径用掉」。

**修法**：取景高度剖面改为飞行前算一次（`buildHeightProfile`），加一条地板
「不低于当前地速 / 0.6 所需的高度」，并让爬升段只许往上、下降段只许往下；
`check:flight` 改用同一条剖面当分母。实测超红线帧 320 → 0，峰值 1.41 → 0.54。

**顺带的一条**：地板里的地速必须量**曲线上的实际位移**，不能用
`progressToDistance` 的导数代替 —— 后者是沿航点折线的弧长，与样条实际走的距离
实测差到 1.83 倍（中位 1.38），用它算出来的地板会低一截，红线照样破。

### D5 航点机场与航班的出发/到达机场不是同一个

| | |
|---|---|
| **症状** | 镜头从 A 机场起飞，`flight.depIata` 却写着 B 机场 |
| **防线** | **脚本**（`check:routes` 比对首尾机场航点 id 与 `flight.depIata`/`arrIata`） |
| **还会再犯吗** | **不会**（被脚本挡住） |

实例：成都—兰州（`ctu-lhw`）的首航点写的是**成都天府（TFU）**，而核实下来
EU1863 从**成都双流（CTU）**起飞。两个航点名字都对、坐标也都对，只是**不是同一个
机场** —— 肉眼几乎看不出来，是核实航班信息时顺带撞见的。

**根因**：同一座城市有两个机场时（成都双流/天府、北京首都/大兴、上海虹桥/浦东），
航点和 `flight` 是两处分别填的，没有任何东西逼它们一致。

**第二例（英国批）**：伦敦—贝尔法斯特记的到达机场是 **BFS（贝尔法斯特国际）**，
但英航从希思罗飞贝尔法斯特固定落 **BHD（乔治·贝斯特城市机场）** —— BFS 是易捷等航司
从别的伦敦机场服务的。城市对没错，错的是**同城两个机场里选错了一个**。同批的
`edi-bfs` 用 BFS 反而是对的，所以不能整批替换，得一条条看。

**修法**：`check:routes` 加断言 —— 首尾机场航点的 id（三字码形态）必须等于
`flight.depIata` / `arrIata`。希腊、奥地利那批用 `athens` / `vienna` 这种城市 slug
作航点 id，不是机场码，规则只在 id 长得像 IATA 三字码时生效。

### E1 README/文档里的数字过期

| | |
|---|---|
| **症状** | 文档写"127 条航线"而实际 295 条，写"301 个地形"而实际 1041 个，写"467 座城市"而实际 691 座 |
| **防线** | **无**（靠约定：以脚本输出为准） |
| **还会再犯吗** | **会** |

**最近一次**：写这份台账当天跑 `check:places`，输出 691 座城市，而 README / CLAUDE.md
里三处都还写着 467 —— 已一并改正。**这类错误每加一批内容就会重犯一次。**

**已采取的缓解**：README 明写"这三行数字如果对不上，以 `check:*` 脚本输出为准"，
并且不在 README 里维护第二份按国家的明细。`docs/routes.md`、
`docs/architecture-metrics.md` 顶部都加了"⚠️ 早期快照，已过期"的说明而不是假装还准。

| | |
|---|---|
| **症状** | CLAUDE.md 写"每条航线一次 ≤3 分钟"，代码里常规上限是 300 秒（5 分钟） |

## 一条方法论上的教训：带着假设去核，但要接受假设被推翻

核到第四波时，希腊（A3 号段）、德国（LH 号段）、英国（BA14xx）连着出现「航班号真实
但飞的是别的城市对」，看起来像是同一批号段被整体串位抄录。于是核波兰那批（LO38xx /
LO39xx，形状一模一样）时，prompt 里明确写了这个怀疑，让子代理优先按这个方向查。

**结果这个假设不成立**：波兰 6 个号各自对应的正是记录里那对城市，一个都没串位。
真正的问题在机型（LOT 支线是 E170/E175/E190/E195 混编排班，不是每个航班号绑死一个
机型）和一个臆造的时长。

**后来又被推翻了三次**，这已经不是偶然：

| 我的假设 | 实际 |
|---|---|
| 波兰 LO38xx/39xx 是号段串位 | **不成立**，6 个号全对，问题在机型 |
| 智利 LA9/LA21/LA61 是洲际号被套用 | **不成立**，确实是国内短途号 |
| 瑞典四位号（SK1042/SK2064）是代管 | **只对一半**：SK2064 是 BRA 代运营，SK1042 反倒是主线自营；三位号的 SK107/SK195 才是 BRA。**位数不是可靠信号** |
| 泰国 TG100 有问题因为「泰航没有 A320」 | **方向对、理由错**：Thai Smile 2024-01 并入泰航后 A320 转入 TG 号段，泰航确实有 A320 飞这条线；真正的问题是 TG100 这个号在当前时刻表里查不到 |
| 泰国皇雀航空 DD108 因破产重整可能已停飞 | **不成立**，仍在正常运营，737-800 也没变 |
| 韩国真航空品牌因大韩收购韩亚而失效 | **尚未生效**：三家整合到 2027-03-17 才完成，当前名称准确 |

**但不是所有怀疑都一样不靠谱** —— 到全部核完为止，两类怀疑的命中率差别很明显：

| 怀疑的类型 | 命中率 | 例子 |
|---|---|---|
| **结构性/制度性**：这个机场还有定期航班吗？这家航司还在吗？这条线被高铁取代了吗？ | **高** | 卢加诺、马斯特里赫特、格罗宁根、柏林—汉堡、巴黎—斯特拉斯堡、竹子航空、Alitalia、SAS 波音 737、蒙古连号序列 —— 基本都成立 |
| **对号码/数字做模式匹配**：这个号形状可疑、这个号段是代管、这个位数说明什么 | **低** | 五次落空一次命中（A6）；「四位号=代管」只对一半；「LA9 是洲际号」不成立 |

**可操作的结论**：核实前值得先问「这家航司/这个机场/这条线在制度层面发生过什么变化」，
不值得花力气去猜号码规律。前者能指出该重点查哪一批，后者只会带偏。

**规律**：我的启发式能可靠地指出「这一批有问题」，但**对具体是什么问题几乎总是猜错**。
所以带假设去核可以（它确实提高了命中率），但必须要求子代理**先独立查证、再回答
假设成不成立**，而不是让它去找支持假设的证据。子代理每次都明确回答了假设不成立，
这是这个流程能用的前提。
