## 5. 做这类批次时的硬性做法（都是踩出来的）

- **子代理一批 ≤55 条，且要求「每条一行表格」**；合并结果时先数行数。给 60–120 条，它会自己分诊、
  把「低风险」的静默跳过，而总结里仍写成「已核」。
- **读它的 finding 正文，不要只看 verdict** —— 出现过 verdict 写 `ok`、而它自己引的证据说相反的情况。
  2026-09-12 那轮还撞到一次相反的好例子：子代理判 campine 那条「问题不在 distinguish 段而在 seeing 段」，
  **上一轮的注释把字段记错了**，照着 verdict 读会直接结案。
- **它给的替换值要过同一套判据**：3 级来源（维基、聚合站、旅游博客）只能证明原值可疑，
  **不能作为替换值的唯一依据**；拿不到 1–2 级来源就记 `unknown`。
- **只删不补**：查无出处又有 3 级反证的具体数字，删掉比换一个「看起来合理」的更好
  （2026-09-12 苏德罗森岭的「长约22公里」就是这么删的）。
- **两说并存时并列写、不要押注**：`yinshan` 长度、`qilian` 团结峰高程、`lake-trichonida` 面积都是这个写法。
- **注意子代理常犯的四种**：把一个时点外推成「此后每年」；替换值本身越界；
  说「正文里没有这句」而其实有（自己按条目 grep 一遍）；中文专名译错。
- **一个会话的 WebSearch 上限是 200 次**，一轮 5 个子代理大致就到顶。要么分会话做，要么调高
  `CLAUDE_CODE_MAX_WEB_SEARCHES_PER_SESSION`。
- 改完 `route-narration.ts` **必须重跑 `npm run gen:anchors`**。
- **人口这类数字，核完要把该机构的发布月份记进 [`data-refresh-calendar.md`](data-refresh-calendar.md)** ——
  发布节奏是核实过程的副产品，当时不记，下一轮还得再查一遍。

## 6. 工具

| 命令 | 做什么 |
|---|---|
| `npm run verify:apply-text -- <findings.json>` | 把替换打进正文 + 写来源注释，并**回头搜**改掉的字还留在哪（含注册表 `source` 留痕） |
| `npm run verify:report -- <findings.json>` | 关 issue / 开 issue / 在总 issue 下留进度评论 / 追加台账一行。**不要手工开 issue** |
| `scripts/verify/mkfindings.py` | 生成 findings.json，并在**生成时**断言 find 在条目内唯一、不跨片段拼接、替换无裸双引号；另带 `apply_direct()` 给「只改写法、不值得开 issue」的批量替换 |
| `npm run check:pending` | **会过期的状态**清单（在建 / 计划 X 年 / 停航 / 公报未发布），⚑ = 承诺的年份已经到了。永远 exit 0 |
| `npm run check:claims` / `:zhen` / `:distance` / `:rvt` / `:routes` | 离线门禁与清单，见 CLAUDE.md「内容准确性」一节 |

⚠️ `verdict: "ok"` 的 finding，`verify:report` **不会自动关 issue**（它只在有实际修正时关）——
核完确认「issue 记的缺陷已经不在了」，要自己补一条评论再关（2026-09-12 的 #216 就是这样）。

`mkfindings.py` 自检：`python3 scripts/verify/mkfindings.py`。
