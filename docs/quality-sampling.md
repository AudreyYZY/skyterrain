# 正确率抽样：随手翻开一句，它错的概率是多少

> 这份文档回答一个此前**从来没有被回答过**的问题。
> 台账 [`verification-ledger.md`](verification-ledger.md) 记的是**覆盖率**，
> 错误分类 [`known-errors.md`](known-errors.md) 记的是**已知错型**，
> 两者都说不出「用户现在看到的内容有多少是对的」。这份文档记的就是这个数。

## 为什么需要它

此前所有对外的进度都是覆盖率口径：「1041 篇地形全部有 `sources:` 留痕」「38 国整国核完一遍」。
**这个口径有两层虚高**：

1. **一轮核实只要在某个条目里改了一句，整条就被算作「核过」**，而同条目另外五段没人看过。
   按字段粒度重算：`npm run gen:verify-status` 的输出是
   **2,199 / 11,395 个字段带核实留痕 ≈ 19%**，不是按条目算的 89%。
2. **「有人核过」不等于「是对的」。** 核过的也可能核错，没核过的也可能本来就对。

而台账里累计逐条裁决过 2,948 条断言、其中 1,935 条有误（66%）这个数**不能当错误率用**：
每一轮核实的对象都是脚本或人挑出来的**可疑句**，是有偏样本，天然富集错误。

真正的错误率只能靠**均匀随机抽样**估计。

## 方法

```bash
npm run sample:claims -- --n=30 --seed=1     # 抽一份可复算的样本
```

- **样本池**：三套内容（地形讲解 / 城市攻略 / 航线解说）的中文正文里，所有
  「可核实的断言句」——带数字、年份、最高级、或「列入 / 设立 / 始建」这类认定的句子。
  注释不进池（那不是对外文案）。当前池大小 **10,635 句**。
- **抽样**：`mulberry32` 伪随机数，**同一个种子永远抽出同一批**，可复算、两次抽样可比较。
- **判据**：`ok` / `wrong` / `unknown` / `n/a` 四种。
  - `unknown` = 查不到能支持也查不到能否定 —— 这是**完全可接受且重要**的结论，
    它量的是「这句话现在根本没人能验证」的比例。
  - `n/a` = 纯观感描述、季节建议、「初来的人最容易犯的错是……」这类**天生不可证伪**的句子。
- ⚠️ **不要挑样本。** 抽到难核的、抽到自己没把握的，照样要核、照样要记进去。
  一旦开始换样本，这个数字就和覆盖率一样没有意义了。

## 第 1 次抽样（2026-09-12，seed=1，n=30）

| 结论 | 条数 |
|---|---|
| `ok` | 24 |
| `wrong` | **2** |
| `unknown` | 0 |
| `n/a` | 4（主观旅行建议 / 框架性表述） |

**错误率 = 2 / 26 可判定句 ≈ 7.7%**（n 很小，置信区间宽，按 Wilson 区间约 **2%–25%**）。
按样本池 10,635 句外推，**全库估计还有 500–900 处错误没被发现**。

抽中的两处错，错法都很细：

| 条目 | 错在哪 | 类型 |
|---|---|---|
| `travel/quy-nhon` | 富吉机场写「在**北面**约 30 公里」，实际在**西北** | 方位词写粗（距离是对的）|
| `terrain/dachstein` | 「三州山」这个称呼被挂到**主峰**头上，它描述的其实是**整个山块**；真正的三州交界点在邻近的托尔施泰因峰 | C1-b-2「真属性挂到错对象」；**而且英文侧原本就写对了（写的是 massif），只有中文侧错** |

**这两处都不是任何离线脚本能抓到的**：方位词没有可比对的基准，「主峰 vs 山块」的范围混淆
在句子内部自洽。它们只能靠逐条联网核实发现 —— 这正是为什么错误率不会靠加脚本降到零。

## 这个数该怎么用

- **对外**：界面底部的核实状态一行（`components/VerificationNote.tsx`）如实写「本篇 N 段中
  M 段有核实留痕，其余依据公开资料整理」。**读者能自己判断该给多少信任，是比「把错全改完」
  更现实、也更诚实的目标** —— 一个人如果事先知道这里没逐条核过，撞见一处错不会推翻他对
  全部内容的信任；如果他以为这里是权威的，一处错就够了。
- **对内**：每推进一大批内容之后**重抽一次**（换种子），看这个数有没有下降。
  它是唯一一个能说明「核实工作到底有没有让内容变好」的指标 —— 覆盖率说不了这件事。

## 下一次抽样

- 下次用 `--seed=2`，同样 n=30；样本量攒到 100 条以上时，置信区间才会收窄到有意义的宽度。
- 也可以按 `--kind=travel` / `--kind=terrain` 分别抽，看哪一套内容错得更多
  （目前的印象是城市攻略的 `identity` / `layout` 段最容易出问题，但**那是印象，不是测量**）。
