  仍存在的问题

  高优先级

  1. speak 和 speakAndWait 完全相同 (lib/speech.ts:134-136)
    - speak 只是调用 speakAndWait，是无用的 wrapper
    - 建议：删除 speak，统一用 speakAndWait
  2. onComplete 回调中 speakAndWait 未 await (ExplorerApp.tsx:229)
    - void speakAndWait(ROUTE_END_LESSON.seeing, ...) — 航线结束语是 fire-and-forget
    - 如果用户在结束语播放中点击新操作，可能出现语音冲突
  3. estimateSpeechDurationSec 死代码 (lib/speech.ts:7-13)
    - 定义了但整个项目没有任何地方使用
    - 建议：删除或在 dwellAfterNarration 中使用来计算合理停留时间
  4. flyToTerrain（非 Wait 版）不再被使用
    - handleSelectTerrain 已改用 flyToTerrainAndWait
    - flyToTerrain 仅在 useImperativeHandle 中定义，外部无调用
    - 建议：删除或标记为 deprecated
  5. 航线飞行 dwellSecAtWaypoint 默认仅 6 秒
    - 对于长讲解（天山 lesson 约 100+ 字），语音可能 20+ 秒
    - dwellAfterNarration 逻辑正确（取 max），但 6 秒的最短停留可能太短
    - 建议：增加到 8-10 秒

  中优先级

  6. routePreparing 状态重复管理
    - CesiumMap 内部有 routePreparing state（用于渲染加载遮罩）
    - ExplorerApp 也有 routePreparing state（用于 UI 状态）
    - 两套状态可能不同步
  7. 无选中地貌时的 loading 反馈
    - 用户点击地貌后，镜头飞行需要 5 秒，期间无任何视觉提示
    - 建议：添加 "正在飞往…" 的过渡状态
  8. 硬编码的飞行时长
    - flyToTerrain / flyToTerrainAndWait 中 duration: 5 是硬编码

  9. preloadRoute 中的 sleep 时间硬编码

    - 应提取为命名常量

 Layout Strategy

 - Right panel: Replace ResizablePanel wrapper with a fixed floating overlay at bottom-right. No resize handle needed —

 - Header: Shrink to a minimal translucent top bar — smaller padding, lighter presence

 - Glass panels: bg-white/[0.04] backdrop-blur-2xl with border border-white/[0.06] — barely visible, let the map

 - Typography: Narration seeing text gets text-base (bigger), section headers use subtle amber gradient feel

 Route Flight Redesign: Continuous Airplane Sightseeing

 Context

 The current route system behaves like a slide presentation: stop → narrate → move. The camera halts at each waypoint,
 waits for narration to finish, then jumps to the next point. This kills the feeling of continuous flight.

 The goal is to make route mode feel like a real commercial airplane sightseeing journey: continuous forward movement,
 narration happening DURING flight, slow graceful transitions near landmarks, and a cinematic documentary pace.

 Current Flow (stop-and-go)

 preloadRoute → for each waypoint:
   flyLeg(from, to)        // camera MOVES, then STOPS at waypoint
   narrateWaypoint(wp)     // camera STATIONARY, speech plays
   dwellAfterNarration()   // camera STATIONARY, waits

 New Flow (continuous flight)

 preloadRoute
 flyToOverview()           // show entire route, dwell 4s
 for each waypoint:
   flyLeg(from, to)        // camera MOVES continuously to waypoint
   beginNarration(wp)      // fire-and-forget: UI updates + speech starts (no await)
   dwell(10s)              // camera STAYS briefly at waypoint
                           // narration is PLAYING during this time
                           // then next flyLeg begins while narration may still be playing

 Key change: narration is non-blocking. Camera doesn't wait for speech to finish.
